Varians-Synchro — User guide

Varians-Synchro aligns the manuscripts of a single work line by line, from their images and the segmentation of their lines (ALTO or PAGE XML). In this way it prepares the alignment files that allow Varians to display each witness beside the edition, with the right manuscript line facing the text.

1. Overview

What Varians-Synchro does

  • It links the lines of two manuscripts. You see the two witnesses side by side, with the outline of each line, and you state which lines of one correspond to which lines of the other. A correspondence can join several lines on each side.
  • It suggests; you decide. From a few anchors that you place, it suggests the intermediate correspondences based on the quantity of text; you check them on the images and validate them.
  • It works relative to a pivot witness. Every other witness is aligned with the pivot. In Varians, the lines of the pivot are located in the edition by its <lb/> elements; the other witnesses follow through their alignment with the pivot.
  • It exports for Varians one alignment file (JSON) per witness, or a complete Varians project, ready to open.

What it does not do

  • It does not transcribe or segment the images: the lines come from recognition software (eScriptorium, Transkribus, Kraken…), as ALTO or PAGE XML files.
  • It does not edit the TEI text: that is the job of Varians.
  • It never modifies your source files (images, ALTO, PAGE, TEI). All its work is stored in the .vsynch project file.

What you need to start

  • For each witness: its images (local files, or a IIIF Manifest) and, for each page to align, an ALTO or PAGE XML file describing its lines.
  • Optionally, the TEI edition of the pivot witness, if it already exists.

The four-step process

The main window follows four steps, listed on the left:

  1. 1 · Add witnesses: declare the manuscripts and their files;
  2. 2 · Associate resources: associate each image with its line file, set the page order and the lines to ignore;
  3. 3 · Align witnesses: align each witness with the pivot;
  4. 4 · Finalize: check, then export to Varians.

Remember to Save the project after each work session. The help opens at any time with Open user guide or F1.

2. First try: the sample project

The demo_local_ALTO/ folder, supplied with the software, contains two small fictitious witnesses, A and B, each with one page of three lines, and their ALTO files. Their text is divided differently, as in two real manuscripts. Ten minutes are enough to go through the whole process.

  1. Copy the demo_local_ALTO folder elsewhere: saving modifies the project file.
  2. Click Open .vsynch and choose exemple.vsynch in the copy.
  3. In 1 · Add witnesses, the witness list shows that A is the pivot (“A — A · pivot”): B will be aligned on it. To choose another pivot, click a witness, check Use this witness as the pivot for aligning witnesses, then click Save witness.
  4. In 3 · Align witnesses, keep A in Technical reference and B in Witness to align, then click Align witnesses.
  5. In the alignment window, click the first line of A, then the first line of B, and press Ctrl+Enter (Link selected lines). Do the same for the third lines. These two correspondences, in green, are your anchors.
  6. Click Align between anchors (text quantity): the software suggests linking the second lines. Click Save selection. The suggestion appears in dashed blue: it needs review.
  7. At the bottom, with the To review filter, choose the suggestion in the list, check it on the images, then click Validate & next.
  8. Close the alignment window and click Save.
  9. In 4 · Finalize, click Create a preconfigured Varians project…, choose an empty folder, then open the newly created project.xml in Varians.

3. Workflow A: create a new Varians project

You are starting an edition: no Varians project exists yet. Varians-Synchro prepares the whole project: witnesses, images, alignments and, if you have it, the TEI edition of the pivot.

In Varians-Synchro

  1. Create the project. New project asks for a name, then for the location of the .vsynch file, which is saved immediately.
  2. Declare the witnesses. In 1 · Add witnesses, add each manuscript with Add witness…: its siglum, its images, its ALTO/PAGE files and, for the pivot only, its TEI edition if there is one. Choose the pivot (see Key concepts): by default, it is the first witness added. Details: Step 1.
  3. Associate images and lines. In 2 · Associate resources, check that each page is associated with the right ALTO/PAGE file and that the pages are in reading order. Mark the lines to ignore: those outside the text you are editing (beginning and end of a passage, running titles, another work on the same page). Details: Step 2.
  4. Align each witness with the pivot. In 3 · Align witnesses, choose the pivot in Technical reference, another witness in Witness to align, and open Align witnesses. Place anchors, let the software suggest the rest, then check and validate. Repeat for each witness. Details: The alignment window.
  5. Save, then, in 4 · Finalize, run Check project consistency… and read the warnings.
  6. Create the Varians project. Create a preconfigured Varians project… writes the project into an empty folder. It contains only validated correspondences: so validate everything that should count before this step. Details: Preconfigured Varians project.

In Varians

  1. File → Open project…, then the newly created project.xml.
  2. Without a TEI edition, the project receives an empty TEI, as for a new transcription in Varians. To prepare the pages and lines of the pivot in it: File → Project settings…, Prepare pivot-witness transcription box, check Prepare pivot-witness <pb/> markers in an empty TEI and, if you wish, Also generate <lb/> markers from ALTO, PAGE or synchronization.
  3. With a TEI edition, it must contain exactly one <lb edRef="#PIVOT"/> per active line of the pivot, in reading order: Varians matches the n-th line of the pivot with the n-th <lb/>. The optional step Link the TEI edition in Varians-Synchro lets you check this before export.
  4. Check the result with View → Witness diagnostics….

4. Workflow B: add a witness to an existing Varians project

Your Varians project already exists and was created from a Varians-Synchro project (or the alignment file of its pivot comes from one). You want to add a new manuscript to it, synchronized with the edition.

The principle. The alignment file of the new witness designates the lines of the pivot by the identifier of their page and their position in that page, as known to your .vsynch project. So you must work in the same .vsynch project as the one used to create the Varians project, and leave the pivot untouched.

In Varians-Synchro

  1. Open .vsynch: open the project that was used to create the Varians project.
  2. In 1 · Add witnesses, add the new manuscript with Add witness… (siglum, images, ALTO/PAGE). Give it the siglum it will have in Varians.
  3. In 2 · Associate resources, associate its pages with their ALTO/PAGE files and mark its lines to ignore.
  4. In 3 · Align witnesses, keep the pivot in Technical reference, choose the new witness in Witness to align, then align and validate.
  5. Save.
  6. In 4 · Finalize, Export JSON for Varians…: choose the pivot as the reference witness, and an empty folder. The file of the new witness is validated/<siglum>.json (validated correspondences); working/<siglum>.json also contains the unvalidated suggestions. See Export JSON for Varians.
Do not modify the pivot (its pages, their ALTO/PAGE files, its ignored lines, its reading order): its lines would change position or number, and would no longer match the <lb/> elements of the edition. If you must modify it, also replace the alignment file of the pivot in Varians with validated/<pivot>.json, and check that its number of lines still equals its number of <lb/> elements.

In Varians

  1. File → Project settings…; in the list of witnesses, Add….
  2. Enter the siglum, the images (Image source) and, in Synchronization file (optional), the file validated/<siglum>.json. Check Copy synchronization into the project: the project then stays complete if you move it.
  3. Check with View → Witness diagnostics…: the new witness must have valid links to the pivot.

Updating a witness already in the project

After completing the alignment of a witness in Varians-Synchro, export again. Then, in Varians, give the witness the new file (Edit… in the project settings), or replace its file in the alignments/ folder of the project. View → Refresh synchronization… (Ctrl+Shift+R) rereads the files without reopening the project.

Varians project that does not come from this .vsynch. The page identifiers differ: Varians then reports that the links in the file match no line of the pivot. You must also replace the alignment file of the pivot with validated/<pivot>.json, which has the same number of lines as its <lb/> elements.

5. Key concepts

ConceptMeaning
Witness, siglumA manuscript (or an early edition). The siglum is its identifier: it can no longer be changed once the witness is saved. As in Varians, it may contain spaces and dots (“BnF lat. 123”): exports derive from it an XML identifier (“BnF_lat._123”), which also names their files, and keep the siglum for display. Two sigla that would give the same identifier (“a” and “A”, “T 2” and “T_2”) are refused when the witness is created, as are names reserved by Windows (CON, NUL…). Keep the siglum used in the Varians project.
Pivot witnessThe reference witness of the project: the other witnesses are aligned with it, and Varians follows it through its <lb/> elements. This choice is technical: it implies nothing about the stemma or about the base manuscript of the edition. The first witness added is the pivot by default; to change it, check the pivot box in the record of another witness. The Technical reference menu in step 3 only chooses the left-hand witness to align; it does not change the pivot of the project.
Physical lineA line described by the ALTO/PAGE file of a page. It is identified by its page and its position in that file. The content of the file is copied into the project on import.
Ignored line (scope)A line outside the text under study. It applies to the witness throughout the project: it is excluded from calculations, from the TEI binding and from exports. Ignoring a line that is already linked removes its links, in all pairs, after confirmation. If the page receives another ALTO/PAGE file, the mark follows the line found identical in that file (same identifier, same text); the page’s other marks are removed, and the confirmation says how many. Removing an ALTO/PAGE file removes the marks of its pages.
Group (correspondence)Lines of the left-hand witness linked to lines of the right-hand witness: 1↔1, 1↔n or n↔m. A line belongs to at most one group per pair.
Group statevalidated, uncertain or proposed. The list of groups shows these states as they are. The To review filter gathers the unvalidated groups.
AnchorA validated correspondence on which suggestions rely. Anchors must follow one another in the same order in both witnesses; at least two are needed.
Confirmed absenceLines of one witness that have no equivalent in the other (omission, lacuna). It applies to one pair, appears in red and produces no link on export.
Unlinked lineAn active line that does not yet belong to any group in the pair (in purple).
Stale groupA group in which a line has changed: usually, the page has received another ALTO/PAGE file. It is never deleted, but it is excluded from anchors, calculations and exports until you revalidate or unlink it.
ProtectionManual groups and validated groups are never replaced by a calculation. Only unvalidated automatic suggestions can be.

6. Step 1: add witnesses

Add witness… opens the record of a new witness; clicking a witness in the list (or one of its resources) opens its record so that you can complete it. For each witness, the list shows its resources and their status (associated pages, imported lines, TEI binding). With the keyboard, Enter or Space on a witness in the list also opens its record.

The witness record

  • Siglum and Description. The siglum can no longer be changed once the witness is saved.
  • Use this witness as the pivot for aligning witnesses. In the pivot’s record, the box is ticked and greyed out: to change the pivot, tick it in another witness’s record.
  • Four groups of resources, each with Add…:
    • Local images: JPEG, PNG, TIFF, WebP or JPEG 2000; images are sorted by name (“2” before “10”);
    • IIIF Manifest: the URL of the Manifest; if it does not respond, the URL is kept, with the status “unavailable”, and Retry queries it again; while it loads, a waiting window lets you cancel;
    • ALTO/PAGE XML files: the format is recognized from the content;
    • TEI XML edition: optional, useful for the pivot.
  • Remove removes the selected resource. A resource added since the record was opened simply disappears from the list. For a resource that is already saved, the software first tells you what removing it entails (pages removed or freed, lines, groups affected); once confirmed, it is marked “−” and removed when you click Save witness. The groups that touched its lines are kept and marked as stale: unlink them afterwards (see Stale groups). No file is deleted from disk.
  • Remove witness… removes the witness from the project, with its synchronisations and TEI editions, after confirmation. The pivot witness cannot be removed: first choose another pivot.
  • Automatically link images and ALTO/PAGE suggests page associations right away (see below).
  • Save witness applies everything at once; Cancel leaves the project unchanged. If the record contains changes, Esc, the window’s close button or Cancel first ask whether to discard them.

7. Step 2: associate resources

Four operations, each for a witness of your choice:

Pages, order and line files

Manage images, their order and ALTO/PAGE associations… shows the pages of the witness, with their thumbnails and their line files.

  • Reading order: drag the pages, or use Move up, Move down, Reverse order.
  • Associate ALTO/PAGE gives the selected page a line file. If the page already had one, the software states how many groups will be affected: they will become stale (see Stale groups). It also says how many ignored lines will lose their mark. An ALTO/PAGE page already associated with another image is refused: its lines would count twice.
  • View page (or a double-click) shows the page and its lines.
  • HD copies of IIIF images: Download selected IIIF images in high resolution… saves the chosen images into an empty folder; Attach an existing HD download… retrieves a previous batch. The Varians project uses these copies if every relevant page has one.
  • External HTR (optional): Export for HTR saves the chosen IIIF images in a ZIP for recognition software; Reimport HTR then associates the resulting ALTO/PAGE files, by name.

These changes take effect immediately: close with Close, then save the project.

Automatic association

Automatically link images and ALTO/PAGE suggests a line file for each page that does not have one yet: first based on names and image references (Unique name), then, if the remaining pages are all local images and exactly as many unlinked ALTO/PAGE pages remain, by pairing them in the natural order of the file names. Check the latter carefully: an offset carries over to the whole series. A file suggested for two pages is flagged in red. Apply links never overwrites an existing association.

Lines to ignore (scope)

Choose lines to ignore on witness images…: on the images, select the lines outside the text under study, even across several pages, then Ignore selected lines (or Restore selected lines). Save scope applies the changes; Cancel changes nothing. The same setting is available in the alignment window (Scope ▾). If you have changed lines, Esc, the close button or Cancel first ask whether to discard these changes.

Link the TEI edition (optional)

Link the TEI edition to ALTO/PAGE lines… matches the <lb edRef="#SIGLUM"/> elements of a TEI edition with the active lines of the witness, in reading order. The numbers must be equal: the window compares them and reports what is blocking (lines to ignore that were not marked, ambiguous readings in an apparatus). Check a few lines, in particular with Beginning and End, on the text and the cropped image, then Confirm bindings.

The binding is not required for export: it serves to check that the number of lines of the pivot matches its <lb/> elements, and it makes the alignment window show the TEI text instead of the HTR text. Its status changes to needs review (sources changed) if the edition, the scope, the order or the segmentation changes.

8. Step 3: align witnesses

Choose the left-hand witness in Technical reference (usually the pivot of the project) and the other witness in Witness to align, then click Align witnesses. There is only one alignment per pair: opening it the other way round reopens the same alignment, with the same witness on the left.

Below the button, the list of pairs already aligned shows their progress (number of groups, linked lines on each side). Double-clicking a pair, or pressing Enter, reopens its alignment; a single click selects it in the two menus.

For export to Varians, each witness must be aligned directly with the pivot: a B↔C alignment is not used for export if the pivot is A.

9. The alignment window

The two witnesses are shown side by side, the reference witness on the left. The line outlines are colored according to their state. All work is done in memory: after closing the window, save the project in the main window. Here, F1 opens this section of the help.

Recommended method

  1. Place anchors. Link a few certain lines: at the beginning, at the end, and where the manuscripts diverge (change of column, lacuna, addition). Select the line or lines on the left and on the right, then Link selected lines (Ctrl+Enter). A group created this way is manual and validated (solid green).
  2. Let the software suggest the rest. Align between anchors (text quantity) calculates, between two anchors, the most probable correspondences based on the quantity of text in each line. A window shows the suggestions: keep the right ones, then Save selection. They are saved as needing review (dashed blue).
  3. Review and validate. At the bottom, choose the To review filter and go through the groups with Next ▶ (F8) and ◀ Previous (Shift+F8). The chosen group appears in pink on both images. Validate & next (Alt+V) validates it and moves to the next one.
  4. Correct. To add a line to a group, select it together with a line of the group and use Link selected lines. To remove a line, select it and use Unlink. A corrected group becomes manual (green) and protected.
  5. Handle absences (see below), then close and save.

Selecting lines

  • Clicking a line selects it (orange) and replaces the selection in that witness, on all its pages.
  • Ctrl+click adds or removes a line; Shift+click selects a run of lines in the reading order of the witness, from one page to the next.
  • Clicking a line that is already linked shows its corresponding lines in the other witness in pink (changing page if needed). Pink is never a selection.
  • Mouse wheel: zoom; drag: move the image; double-click: zoom to the line. Fit page shows the whole page.
  • HTR text shows the text of the lines below the image (the TEI text if a TEI binding is valid). Line outlines hides or shows the outlines; Clear selection empties the selection.

Visible frames limits the display to Unlinked lines or to Automatic links to review, to spot what remains to be done.

The list of groups

At the bottom, Review filters the groups: All groups, To review, Validated, Confirmed absences, Stale. Each group is described there by its state and its lines, named page:line (page label, line position). You can select several groups (Ctrl, Shift) and use Validate selected….

Recalculate gap… redoes the suggestions for the interval that follows the chosen anchor only, for example after adding an anchor.

Confirmed absences

When lines of one witness have no equivalent in the other, select them on one side only, then More actions → Confirm absence for selected lines (Ctrl+Shift+A). They are no longer “unlinked” and appear in red. Remove selected absences from review list cancels an absence chosen with the Confirmed absences filter.

Stale groups

Giving a page another ALTO/PAGE file (a corrected segmentation) can change its lines. Before the replacement, the software states how many groups cite these lines; afterwards, the groups in which a line has changed are marked “[stale]”. The Stale filter lists them. After checking them on the images, Revalidate… restores them; otherwise, unlink them. The corrected reading order of the page is reset.

Other operations

  • Delete selected group(s) from list and Mark as uncertain act on the groups chosen in the list.
  • Suggest using HTR (optional) looks for correspondences based on the similarity of the HTR text of the lines. Nothing is preselected: choose the suggestions to keep.
  • Reading order and intervals… corrects the order of the pages, regions (columns) and lines of a witness, when the segmentation does not give it correctly, and shows the intervals between anchors.
  • Old geometric interpolation (compatibility) and Old residual-lines tool (compatibility) are old methods, kept for projects that used them.

The Text view (optional) tab shows the lines of both witnesses as text. Commands act on the selection in the displayed tab.

10. Step 4: finalize and export

Refresh summary summarizes the witnesses and the alignments, and reports changed lines or missing files.

Checking consistency

Check project consistency… checks the project without changing anything: active lines and associated pages of each witness, validated groups and absences of each pair, missing or stale references, missing files. It also reports an ALTO/PAGE page associated with two images, and a PAGE file that this version reads differently from when it was imported (nested groups or regions): associating it again would make stale the groups that touch its lines. Run it before each export.

Preconfigured Varians project

Create a preconfigured Varians project… writes, into an empty folder, a project that Varians opens as it is:

  • project.xml: the witnesses, their images (IIIF Manifest, or paths of the local images) and the pivot;
  • xml/edition.xml: the TEI edition of the pivot, or an empty TEI if it has none;
  • alignments/<siglum>.json: the alignment file of each witness, validated correspondences only;
  • rendering/, i18n/, web_output/: the usual folders of a Varians project;
  • RAPPORT_EXPORT_VARIANS.txt: the export report;
  • possibly iiif/: the HD copies of the IIIF images, if every relevant page has one.

The images stay where they are: the project points to them (the lines are in the alignment files). Export is refused if the folder is not empty, if the pivot has several TEI editions, if its TEI binding needs review (sources changed) (redo it: otherwise its <lb/> would face other lines), if a witness mixes IIIF and local images, or if a file cannot be found.

Export JSON for Varians

Export JSON for Varians… is used to add or update witnesses in an existing Varians project (Workflow B). Choose the reference witness (the pivot of the Varians project), confirm, then choose an empty folder. The software writes into it:

  • validated/<siglum>.json: one file per witness, validated correspondences only;
  • working/<siglum>.json: the same, plus the unvalidated suggestions;
  • rapport_export.json: the counts and checks of the export.

Varians does not know the states used by Varians-Synchro: import validated/, except for a deliberate test. Only direct alignments with the reference witness are exported, with no inference through a third witness. If a witness has no exportable correspondence, the software says so before the export, and gives the reason.

11. Format of the alignment files (JSON)

One file per witness, in UTF-8, in the tei-manuscript-alignment format, version 1, which Varians reads. The file of the pivot describes its lines; the file of each other witness describes its own lines and links them to the lines of the pivot.

Root

FieldContent
meta.format"tei-manuscript-alignment".
meta.format_version1.
meta.witnessThe siglum of the witness described.
meta.base_witnessThe siglum of the pivot (reference witness).
meta.role"base" for the pivot, "secondary" for the other witnesses.
meta.source"Varians-Synchro".

meta.editorial_tei_alignment"NOT_ESTABLISHED": the file contains no link to the TEI; it is Varians that matches the lines of the pivot with its <lb/> elements.

What Varians does with them

  • The lines in the file of the pivot, in file order, correspond one by one to the <lb edRef="#PIVOT"/> elements of the edition: the first line to the first <lb/>, and so on. Varians checks that the numbers are equal.
  • A pivot key is page_id::line: it remains valid as long as the page keeps its identifier and its ALTO/PAGE file. This is why the new witness of an existing project must be aligned in the same .vsynch project (Workflow B).
  • When the text reaches a line of the pivot, Varians shows, in each other witness, the line or lines whose base_keys designate it.

12. Files, backups and troubleshooting

The project file

  • All the work is in the .vsynch file: witnesses, content of the imported ALTO/PAGE files, associations, ignored lines, reading order, alignments. The source files are never modified.
  • Saving is safe: the file is replaced in a single operation, and the previous version is kept in <project>.vsynch.bak. To go back, copy this .bak file under a new name ending in .vsynch and open it.
  • There is no “Save As” command: to keep a version, copy the .vsynch file.
  • Keep the images, ALTO/PAGE files and TEI files in the folder of the .vsynch file or in its subfolders: they are saved with a relative path, and the project can be moved or copied with that folder (like the supplied sample). A file located elsewhere is saved with its full path.
  • Project received from someone else: if the .vsynch file points to files outside its folder (a path with ..) or on a network share, the software lists them when opening it and asks whether to read them (“No” by default). If you refuse, these files are treated as missing, and their paths are saved unchanged; if you accept, the answer is remembered for this project.
  • Modifying an ALTO/PAGE file on disk after import does not change the project; the summary reports it. For a corrected segmentation, import the new file and associate it with the page (the affected groups become stale).
  • Closing the software, or opening or creating a project, offers to save the current changes.

Common problems

  • “Link ALTO pages to both witnesses before aligning them”: one of the two witnesses does not yet have any page associated with a line file (Step 2).
  • IIIF image unavailable: the server is not responding; the associations are not lost. Try again later, or download HD copies.
  • IIIF Manifest unavailable: it did not respond when the witness was added; its URL is kept and the summary says so. In 1 · Add witnesses, click the witness, then Retry: the software tells you whether the Manifest responded and how many pages it has; Save witness keeps the result.
  • Line frames offset on the image: the image and the ALTO/PAGE file do not have the same proportions (the status bar reports it); check that the file really belongs to this image.
  • Export refused: the chosen folder is not empty, the pivot’s TEI binding needs review, or two sigla give the same file name (older project; see Key concepts).
  • In Varians, the lines of the pivot do not match the text: the number of <lb edRef="#PIVOT"/> elements differs from the number of active lines of the pivot (lines to ignore that were not marked, or missing <lb/> elements). Witness diagnostics… in Varians and the TEI binding in Varians-Synchro help to find the discrepancy.
  • In Varians, the links in the file match no line of the pivot: the alignment file of the pivot does not come from the same .vsynch project (see Workflow B).
  • With Spyder: run run.py; the software opens in a separate process, so as not to disturb the Spyder console. The startup log is in ~/.varians_synchro/logs.
