Varians-Synchro — ユーザーガイド

Varians-Synchro は、同じ作品の写本どうしを、その画像と行の領域分割（ALTO または PAGE XML）をもとに、行単位で整列します。こうして作成される同期ファイルによって、Varians は各伝本を校訂版の隣に表示し、本文の向かいに写本の該当する行を示すことができます。

1. 概要

Varians-Synchro でできること

  • 二つの写本の行を結び付けます。 二つの伝本が各行の輪郭とともに並べて表示され、一方のどの行が他方のどの行に対応するかを利用者が指定します。一つの対応には、両側それぞれに複数の行を含めることができます。
  • ソフトウェアが提案し、判断するのは利用者です。 利用者が置いたいくつかのアンカーをもとに、その間の対応をテキスト量から提案します。提案は画像上で確認し、承認します。
  • ピボット伝本を軸に作業します。 ほかの各伝本はピボット伝本に対して整列されます。Varians では、ピボット伝本の行は校訂版の中でその <lb/> によって示され、ほかの伝本はピボット伝本との整列によってそれに追従します。
  • Varians 用に書き出します。 伝本ごとに一つの同期ファイル（JSON）、またはそのまま開ける完全な Varians プロジェクトを書き出します。

Varians-Synchro がしないこと

  • 画像の翻刻も領域分割も行いません。行は認識ソフトウェア（eScriptorium、Transkribus、Kraken…）から、ALTO または PAGE XML ファイルとして得られます。
  • TEI テキストは編集しません。それは Varians の役割です。
  • 元のファイル（画像、ALTO、PAGE、TEI）を変更することはありません。作業内容はすべてプロジェクトファイル .vsynch に保存されます。

始めるのに必要なもの

  • 各伝本について：その画像（ローカルファイル、または IIIF Manifest）と、整列する各ページについて、その行を記述した ALTO または PAGE XML ファイル。
  • 任意で、ピボット伝本の TEI 校訂本文（すでにある場合）。

インストールと起動

  • すぐに使える版。 いちばん簡単な方法です。Python も含めて何もインストールする必要がなく、Windows、macOS（Apple シリコンまたは Intel）、Linux 用があります。リリースのページ（https://github.com/MarjorieBurghart/Varians-Synchro/releases）から入手してください。アーカイブを展開して Varians-Synchro を起動します。初回起動時のシステムの警告を通過する方法は、README-ja.txt ファイルに書かれています（このソフトウェアには署名がありません）。サンプルプロジェクト demo_local_ALTO はプログラムの隣にあります。更新するには、フォルダーを新しい版のものと置き換えます。プロジェクトと設定は別の場所にあります。
  • Python で使う。 Python 3.10 以降と PySide6 が必要です：pip install -r requirements.txt のあと python run.py（Windows では start_windows.bat、macOS と Linux では start_unix.sh）。
  • インストールの確認。 Varians-Synchro --self-test report.json（Python では python run.py --self-test report.json）は、翻訳、ヘルプ、リソース、サンプルプロジェクト、Varians への書き出しを含む同期 1 件、ウィンドウを数秒で確認し、報告を書き出します。各システムでの正確なコマンドは README-ja.txt にあります。この報告を問題の報告に添付してください：https://github.com/MarjorieBurghart/Varians-Synchro/issues。

4 つのステップ

メインウィンドウでは、左側に示された 4 つのステップに沿って作業します。

  1. 1 · 伝本の追加：写本とそのファイルを登録します。
  2. 2 · 資料の関連付け：各画像をその行ファイルに結び付け、ページの順序と無視する行を設定します。
  3. 3 · 伝本の整列：各伝本をピボット伝本に対して整列します。
  4. 4 · 完了：検査を行い、Varians へ書き出します。

作業を終えるたびに、プロジェクトを保存してください。ヘルプはいつでもユーザーガイドを開くまたは F1 で開けます。

2. はじめての試用：サンプルプロジェクト

ソフトウェアに付属する demo_local_ALTO/ フォルダーには、架空の小さな伝本 A と B が ALTO ファイルとともに入っています。どちらも 3 行からなる 1 ページだけの伝本です。実際の二つの写本と同じように、本文の行の区切り方が異なります。10 分ほどで、作業の流れ全体をひととおり試せます。

  1. demo_local_ALTO フォルダーを別の場所にコピーしてください。保存するとプロジェクトファイルが変更されるためです。
  2. .vsynch を開くをクリックし、コピーしたフォルダーにある exemple.vsynch を選びます。
  3. 1 · 伝本の追加の伝本一覧に、A がピボット伝本であることが表示されます（「A — A · 基準」）。B はこの伝本に整列されます。別のピボット伝本を選ぶには、伝本をクリックし、この伝本を整列のピボット伝本にするにチェックを入れてから、伝本を保存をクリックします。
  4. 3 · 伝本の整列で、技術的なピボット伝本のメニューは A、比較する伝本のメニューは B のままにして、伝本を整列をクリックします。
  5. 同期ウィンドウで、A の 1 行目、続いて B の 1 行目をクリックし、Ctrl+Enter（行を関連付ける）を押します。3 行目どうしについても同じ操作をします。緑で表示されるこの二つの対応が、アンカーになります。
  6. アンカー間を整列（テキスト）をクリックすると、2 行目どうしを結び付ける提案が示されます。選択内容を保存をクリックします。提案は青の破線で表示されます。これは確認が必要な状態です。
  7. 下部で要確認フィルターを使い、一覧から提案を選んで画像上で確認し、承認して次へをクリックします。
  8. 同期ウィンドウを閉じ、保存をクリックします。
  9. 4 · 完了で入力済み Varians プロジェクトを作成…をクリックし、空のフォルダーを選んでから、作成された project.xml を Varians で開きます。

3. ワークフロー A：新しい Varians プロジェクトを作成する

校訂作業をこれから始めるところで、Varians プロジェクトはまだない場合です。Varians-Synchro がプロジェクト全体を準備します：伝本、画像、同期、そしてピボット伝本の TEI 校訂本文（ある場合）。

Varians-Synchro での作業

  1. プロジェクトを作成する。 新規プロジェクトは名前を尋ね、続いて .vsynch ファイルの保存先を尋ねます。ファイルはただちに保存されます。
  2. 伝本を登録する。 1 · 伝本の追加で、伝本を追加…を使って各写本を追加します：シグラム、画像、ALTO/PAGE ファイル、そしてピボット伝本についてのみ、TEI 校訂本文があればそれも指定します。ピボット伝本を選びます（基本概念を参照）。既定では最初に追加した伝本がピボット伝本になります。詳細：ステップ 1。
  3. 画像と行を関連付ける。 2 · 資料の関連付けで、各ページが正しい ALTO/PAGE ファイルに関連付けられていること、ページが読み順に並んでいることを確認します。無視する行、つまり校訂する本文の範囲外にある行（対象箇所の前後、柱題、同じページにある別の作品）を指定します。詳細：ステップ 2。
  4. 各伝本をピボット伝本に対して整列する。 3 · 伝本の整列で、技術的なピボット伝本のメニューでピボット伝本を、比較する伝本のメニューでほかの伝本を選び、伝本を整列を開きます。アンカーを置き、残りはソフトウェアに提案させ、確認して承認します。これを伝本ごとに繰り返します。詳細：同期ウィンドウ。
  5. 保存してから、4 · 完了でプロジェクトの整合性を検査…を実行し、警告を読みます。
  6. Varians プロジェクトを作成する。 入力済み Varians プロジェクトを作成…は、空のフォルダーにプロジェクトを書き出します。含まれるのは承認済みの対応だけです。したがって、反映させたい対応はすべて、この段階より前に承認しておいてください。詳細：入力済み Varians プロジェクト。

Varians での作業

  1. ファイル → プロジェクトを開く…で、作成された project.xml を開きます。
  2. TEI 校訂本文がない場合、Varians で新しい翻刻を始めるときと同じく、プロジェクトには空の TEI が入ります。そこにピボット伝本のページと行を用意するには、ファイル → プロジェクト設定…のピボット伝本から転写の枠組みを準備欄で、空のTEIにピボット伝本の<pb/>（改ページ）を生成するにチェックを入れ、必要に応じてALTO・PAGE・同期データから<lb/>（改行）も生成するにもチェックを入れます。
  3. TEI 校訂本文がある場合、その校訂本文には、ピボット伝本の有効な行 1 行につきちょうど 1 つの <lb edRef="#PIVOT"/> が、読み順に含まれていなければなりません。Varians はピボット伝本の n 番目の行を n 番目の <lb/> に対応させるからです。Varians-Synchro の任意のステップTEI 校訂本文の対応付けを使えば、書き出しの前にこれを確認できます。
  4. 表示 → 写本の状態を診断…で結果を確認します。

4. ワークフロー B：既存の Varians プロジェクトに伝本を追加する

Varians プロジェクトがすでにあり、それが Varians-Synchro のプロジェクトから作成されている場合（または、そのピボット伝本の同期が Varians-Synchro のプロジェクトに由来する場合）です。そこに新しい写本を、校訂版と同期させて追加します。

原則。 新しい伝本の同期ファイルは、ピボット伝本の行を、そのページの識別子とページ内での番号によって指します。これらはお使いの .vsynch プロジェクトが把握しているとおりのものです。したがって、Varians プロジェクトの作成に使ったのと同じ .vsynch プロジェクトで作業し、ピボット伝本には手を加えないでください。

Varians-Synchro での作業

  1. .vsynch を開く：Varians プロジェクトの作成に使ったプロジェクトを開きます。
  2. 1 · 伝本の追加で、伝本を追加…を使って新しい写本を追加します（シグラム、画像、ALTO/PAGE）。シグラムには、Varians で使うシグラムを付けてください。
  3. 2 · 資料の関連付けで、そのページを ALTO/PAGE ファイルに関連付け、無視する行を指定します。
  4. 3 · 伝本の整列で、技術的なピボット伝本のメニューはピボット伝本のままにし、比較する伝本のメニューで新しい伝本を選んで、整列し、承認します。
  5. 保存します。
  6. 4 · 完了でVarians 用 JSON を書き出す…を選び、参照伝本としてピボット伝本を、また空のフォルダーを選びます。新しい伝本のファイルは validated/<シグラム>.json（承認済みの対応）です。working/<シグラム>.json には未承認の提案も含まれます。Varians 用 JSON の書き出しを参照してください。
ピボット伝本は変更しないでください（ページ、その ALTO/PAGE ファイル、無視した行、読み順）。変更すると行の番号や数が変わり、校訂版の <lb/> と対応しなくなります。どうしても変更する場合は、Varians のピボット伝本の同期も validated/<pivot>.json で置き換え、その行数が引き続き <lb/> の数と一致していることを確認してください。

Varians での作業

  1. ファイル → プロジェクト設定…を開き、伝本の一覧で追加…をクリックします。
  2. シグラムと画像（画像ソース）を指定し、同期ファイル（任意）には validated/<シグラム>.json ファイルを指定します。同期データをプロジェクトへコピーにチェックを入れてください。こうしておけば、プロジェクトを移動しても欠けるものがありません。
  3. 表示 → 写本の状態を診断…で確認します。新しい伝本に、ピボット伝本への有効なリンクがなければなりません。

既存の伝本を更新する

Varians-Synchro で伝本の整列を補ったら、もう一度書き出してから、Varians でその伝本に新しいファイルを指定する（プロジェクト設定の編集…）か、プロジェクトの alignments/ フォルダーにあるそのファイルを置き換えます。表示 → 同期データを再読み込み…（Ctrl+Shift+R）で、プロジェクトを開き直さずにファイルを読み直せます。

この .vsynch から作成されていない Varians プロジェクトの場合。 ページの識別子が異なるため、Varians は、ファイルのリンクがピボット伝本のどの行にも対応しないと報告します。ピボット伝本の同期も validated/<pivot>.json で置き換える必要があり、その行数は <lb/> の数と同じでなければなりません。

5. 基本概念

用語意味
伝本、シグラム写本（または古い刊本）。シグラムはその識別子です。伝本を保存した後は変更できません。Varians と同じく、空白やピリオドを含めることができます（「BnF lat. 123」）。書き出しでは、そこから XML 識別子（「BnF_lat._123」）を作り、書き出すファイルの名前にも使います。シグラムそのものは表示用に保持されます。同じ識別子になる二つのシグラム（「a」と「A」、「T 2」と「T_2」）や、Windows の予約名（CON、NUL など）は、伝本の作成時に拒否されます。Varians プロジェクトのシグラムをそのまま使ってください。
ピボット伝本プロジェクトの基準となる伝本です。ほかの伝本はこれに対して整列され、Varians はその <lb/> によってこの伝本をたどります。この選択は技術的なもので、ステンマについても、校訂版の底本についても、何ら前提とするものではありません。既定では最初に追加した伝本がピボット伝本です。変更するには、別の伝本の編集画面でピボット伝本のチェックボックスにチェックを入れます。ステップ 3 の技術的なピボット伝本のメニューは、整列する左側の伝本を選ぶだけで、プロジェクトのピボット伝本は変わりません。
物理行ページの ALTO/PAGE ファイルに記述された行です。ページと、そのファイル内での番号によって識別されます。ファイルの内容は、取り込み時にプロジェクトにコピーされます。
無視した行（対象範囲）研究対象の本文の範囲外にある行です。その伝本についてプロジェクト全体で有効で、計算、TEI の対応付け、書き出しから除外されます。すでに関連付けられた行を無視すると、確認の後、すべてのペアでその関連付けが解除されます。ページに別の ALTO/PAGE ファイルを割り当てると、無視の印は、そのファイルの中で同一と確認できた行（同じ識別子、同じ本文）に引き継がれます。ページのその他の印は解除され、確認画面にその数が表示されます。ALTO/PAGE ファイルを取り除くと、そのページの印は解除されます。
グループ（対応）左側の伝本の行と、右側の伝本の行とを結び付けたものです：1↔1、1↔n、n↔m。一つの行は、ペアごとに最大一つのグループにしか属しません。
グループの状態validated（承認済み）、uncertain（未確定）、proposed（提案）のいずれかです。グループの一覧にはこれらがそのまま表示されます。要確認フィルターは、未承認のグループをまとめて表示します。
アンカー提案の拠り所となる承認済みの対応です。アンカーは両方の伝本で同じ順序に並んでいなければならず、少なくとも二つ必要です。
確定した欠落一方の伝本の行のうち、もう一方の伝本に対応するもののない行（脱落、欠損）です。ペアごとに有効で、赤で表示され、書き出しではリンクを生成しません。
未対応の行有効な行のうち、そのペアでまだどのグループにも属していない行です（紫）。
失効したグループ行の一つが変更されたグループです。通常は、ページに別の ALTO/PAGE ファイルが割り当てられた場合です。削除されることはありませんが、再承認するか関連付けを解除するまで、アンカー、計算、書き出しから除外されます。
保護手動のグループと承認済みのグループが、計算によって置き換えられることはありません。置き換えられるのは、未承認の自動提案だけです。

6. ステップ 1：伝本の追加

伝本を追加…は新しい伝本の編集画面を開きます。一覧の伝本（またはその資料の一つ）をクリックすると、その伝本の編集画面が開き、情報を補えます。一覧には、伝本ごとに資料とその状態（関連付け済みのページ、取り込んだ行、TEI の対応付け）が表示されます。キーボードでは、一覧の伝本で Enter または Space を押しても編集画面が開きます。

伝本の編集画面

  • シグラムと説明。シグラムは、伝本を保存した後は変更できません。
  • この伝本を整列のピボット伝本にする。ピボット伝本の編集画面では、このチェックボックスはオンのまま灰色表示になります。ピボットを変えるには、別の伝本の編集画面でオンにしてください。
  • 4 種類の資料（それぞれに追加…があります）：
    • ローカル画像：JPEG、PNG、TIFF、WebP、JPEG 2000 に対応します。画像は名前順に並べられます（「2」は「10」より前）。
    • IIIF Manifest：Manifest の URL を指定します。Manifest が応答しない場合も、URL は利用できない状態として保持され、再試行で再度問い合わせられます。読み込み中は、待機ウィンドウで中止できます。
    • ALTO/PAGE-XML ファイル：形式は内容から判別されます。
    • TEI XML 校訂本文：任意です。ピボット伝本の場合に役立ちます。
  • 削除で選択した資料を削除します。編集画面を今回開いている間に追加した資料は、一覧から消えるだけです。保存済みの資料では、まず削除の影響（削除または解放されるページ、行、影響を受けるグループ）が表示され、確認すると「−」が付き、伝本を保存で削除されます。その行に関わっていたグループは失効として残るので、後で関連付けを解除してください（失効したグループを参照）。ディスク上のファイルは削除しません。
  • 伝本を削除…で、確認後に伝本をその同期と TEI 版とともにプロジェクトから削除します。ピボット伝本は削除できません。先に別のピボット伝本を選んでください。
  • 画像と ALTO/PAGE を自動で関連付けるは、その場でページの関連付けを提案します（後述を参照）。
  • 伝本を保存はすべてを一括して適用します。キャンセルでは、プロジェクトは何も変更されません。編集画面に変更がある場合、Esc、ウィンドウの閉じるボタン、キャンセルのいずれでも、まず変更を破棄するかどうかを尋ねます。

7. ステップ 2：資料の関連付け

四つの操作があり、いずれも対象の伝本を選んで行います。

ページ、順序、行ファイル

画像・順序・ALTO/PAGE の関連付けを管理…は、伝本のページを、サムネイルと行ファイルとともに表示します。

  • 読み順：ページをドラッグするか、上へ、下へ、順序を反転を使います。
  • ALTO/PAGE を関連付けるは、選んだページに行ファイルを割り当てます。すでに割り当てられていた場合は、影響を受けるグループの数が表示されます。それらのグループは失効します（失効したグループを参照）。無視の印を失う行の数も表示されます。すでに別の画像に関連付けられている ALTO/PAGE のページは拒否されます（その行が二重に数えられるため）。
  • ページを表示（またはダブルクリック）で、ページとその行が表示されます。
  • IIIF 画像の HD コピー：選択した IIIF 画像を HD でダウンロード…は、選んだ画像を空のフォルダーに保存します。ダウンロード済み HD セットを登録…は、以前にダウンロードしたセットを再び登録します。必要なページすべてにコピーがある場合、Varians プロジェクトはこれらのコピーを使用します。
  • 外部 HTR（任意）：HTR 用に書き出すは、選んだ IIIF 画像を認識ソフトウェア用の ZIP に保存します。HTR を再取り込みは、その後に得られた ALTO/PAGE ファイルを、名前に基づいて関連付けます。

これらの変更はただちに反映されます。閉じるで閉じてから、プロジェクトを保存してください。

自動で関連付ける

画像と ALTO/PAGE を自動で関連付けるは、まだ行ファイルのない各ページに行ファイルを提案します。まず名前と画像の参照情報から（一意の名前）、次に、残りのページがすべてローカル画像で、関連付けられていない ALTO/PAGE ページがちょうど同じ数だけ残っている場合には、ファイル名の自然順に対応させて提案します。特に後者を確認してください。一つずれると、以降のすべてのページに及びます。同じファイルが二つのページに提案された場合は赤で示されます。関連付けを適用は、既存の関連付けを上書きしません。

無視する行（対象範囲）

伝本の画像で無視する行を指定…：研究対象の本文の範囲外にある行を、複数のページにまたがっていても画像上で選択し、選択行を無視する（または選択行を対象に戻す）をクリックします。対象範囲を保存で適用され、キャンセルでは何も変更されません。同じ設定は同期ウィンドウ（対象範囲 ▾）にもあります。行を変更した場合、Esc、閉じるボタン、キャンセルのいずれでも、まずその変更を破棄するかどうかを尋ねます。

TEI 校訂本文の対応付け（任意）

TEI 校訂本文と ALTO/PAGE 行を対応付ける…は、TEI 校訂本文の <lb edRef="#シグラム"/> を、伝本の有効な行と読み順に照合します。両者の数は等しくなければなりません。ウィンドウはそれらを比較し、妨げとなっている原因（無視する行の指定漏れ、校異中の曖昧な読み）を示します。特に先頭と末尾を使って、いくつかの行をテキストと切り出した画像で確認し、対応付けを確定をクリックします。

この対応付けは書き出しには必要ありません。ピボット伝本の行数がその <lb/> の数と確かに一致することを確認するためのもので、同期ウィンドウでは HTR テキストの代わりに TEI テキストが表示されるようになります。校訂本文、対象範囲、順序、領域分割のいずれかが変わると、状態は要再確認（資料が変更されています）になります。

8. ステップ 3：伝本の整列

技術的なピボット伝本のメニューで左側の伝本（通常はプロジェクトのピボット伝本）を、比較する伝本のメニューでもう一方の伝本を選び、伝本を整列をクリックします。同期はペアごとに一つしかありません。逆の向きで開いても同じ同期が開き、左側の伝本も同じです。

ボタンの下にある整列済みペアの一覧には、それぞれの進み具合（グループ数、両側で関連付けられた行）が表示されます。ペアをダブルクリックするか Enter を押すと、その同期が再び開きます。クリックすると、そのペアが二つのメニューで選択されます。

Varians へ書き出すには、各伝本がピボット伝本に対して直接整列されていなければなりません。ピボット伝本が A の場合、B↔C の整列は書き出しには使われません。

9. 同期ウィンドウ

二つの伝本が並べて表示され、参照伝本は左側です。行の輪郭は状態に応じて色分けされます。作業はすべてメモリ上で行われます。ウィンドウを閉じた後、メインウィンドウでプロジェクトを保存してください。ここで F1 を押すと、ヘルプのこの節が開きます。

推奨する手順

  1. アンカーを置く。 確実な行をいくつか、冒頭、末尾、そして写本どうしが食い違う箇所（段の変わり目、欠損、加筆）で結び付けます。左右それぞれで 1 行または複数行を選び、行を関連付ける（Ctrl+Enter）を実行します。こうして作成したグループは手動かつ承認済みです（緑の実線）。
  2. 残りを提案させる。 アンカー間を整列（テキスト）は、二つのアンカーの間で、各行のテキスト量から最も確からしい対応を計算します。提案はウィンドウに表示されるので、適切なものを残して選択内容を保存をクリックします。保存された提案は要確認の状態になります（青の破線）。
  3. 確認して承認する。 下部で要確認フィルターを選び、次へ ▶（F8）と◀ 前へ（Shift+F8）でグループを順に見ていきます。選んだグループは、両方の画像上でピンクで表示されます。承認して次へ（Alt+V）は、そのグループを承認して次のグループに進みます。
  4. 修正する。 グループに行を加えるには、その行をグループ内の行と一緒に選択し、行を関連付けるを実行します。行を外すには、その行を選択して関連付けを解除を実行します。修正したグループは手動（緑）になり、保護されます。
  5. 欠落を処理し（後述を参照）、ウィンドウを閉じて保存します。

行を選択する

  • 行をクリックするとその行が選択され（オレンジ）、その伝本の全ページにわたる選択がこれに置き換わります。
  • Ctrl+クリックで行を追加または除外します。Shift+クリックで、伝本の読み順に沿って、ページをまたいで連続する行を選択します。
  • すでに関連付けられた行をクリックすると、もう一方の伝本で対応する行がピンクで表示されます（必要ならページが切り替わります）。ピンクは選択ではありません。
  • ホイール：拡大縮小。ドラッグ：画像の移動。ダブルクリック：行を拡大。全体表示でページ全体が表示されます。
  • HTR テキストは、画像の下に行のテキストを表示します（TEI の対応付けが有効な場合は TEI テキスト）。行の輪郭は輪郭の表示・非表示を切り替え、選択を解除は選択を空にします。

表示する輪郭の設定で表示を未対応の行または要確認の自動対応に絞り込むと、残りの作業を見つけやすくなります。

グループの一覧

下部の確認のメニューでグループを絞り込みます：すべてのグループ、要確認、承認済み、確定した欠落、失効。各グループは状態と行によって示され、行は ページ:行（ページのラベル、行の番号）の形で表されます。複数のグループを選択して（Ctrl、Shift）、選択内容を承認…を実行できます。

局所再計算…は、選んだアンカーに続く区間だけについて提案をやり直します。たとえばアンカーを追加した後に使います。

確定した欠落

一方の伝本の行に、もう一方の伝本で対応するものがない場合は、それらの行を片側だけで選択し、その他の操作 → 選択した行の欠落を確定（Ctrl+Shift+A）を実行します。それらの行は「未対応」ではなくなり、赤で表示されます。一覧から選択した欠落を解除は、確定した欠落フィルターで選んだ欠落を取り消します。

失効したグループ

ページに別の ALTO/PAGE ファイル（修正した領域分割）を割り当てると、その行が変わることがあります。置き換えの前に、これらの行を参照しているグループの数が表示されます。置き換えの後、行が変わったグループには「［失効］」の印が付きます。失効フィルターでそれらが一覧表示されます。画像上で確認した後、再承認…で有効な状態に戻します。そうでなければ関連付けを解除します。そのページについて修正した読み順はリセットされます。

その他の操作

  • 一覧から選択グループを削除と未確定としてマークは、一覧で選んだグループに作用します。
  • HTR から候補を提案（任意）は、行の HTR テキストの類似度から対応を探します。あらかじめ選択されているものはないので、残す提案を選んでください。
  • 読書順と区間…は、領域分割から正しい順序が得られない場合に、伝本のページ、領域（段）、行の順序を修正し、アンカー間の区間を表示します。
  • 旧幾何学的補間（互換性）と旧残余行補完（互換性）は以前の方法で、それらを使っていたプロジェクトのために残されています。

テキスト表示（任意）タブには、二つの伝本の行がテキストで表示されます。コマンドは、表示中のタブでの選択に作用します。

10. ステップ 4：完了と書き出し

概要を更新は、伝本と同期の概要を示し、変更された行や見つからないファイルを報告します。

整合性の検査

プロジェクトの整合性を検査…は、何も変更せずにプロジェクトを検査します：各伝本の有効な行と関連付け済みのページ、各ペアの承認済みグループと欠落、欠けている参照や失効した参照、見つからないファイル。二つの画像に関連付けられた ALTO/PAGE のページや、本バージョンが取り込み時とは異なる方法で読む PAGE ファイル（入れ子のグループや領域）も報告します。そのファイルを関連付け直すと、その行に関わるグループは失効します。書き出しの前には毎回実行してください。

入力済み Varians プロジェクト

入力済み Varians プロジェクトを作成…は、Varians がそのまま開けるプロジェクトを空のフォルダーに書き出します：

  • project.xml：伝本、その画像（IIIF Manifest、またはローカル画像のパス）、ピボット伝本。
  • xml/edition.xml：ピボット伝本の TEI 校訂本文。ない場合は空の TEI。
  • alignments/<シグラム>.json：各伝本の同期（承認済みの対応のみ）。
  • rendering/、i18n/、web_output/：Varians プロジェクトの通常のフォルダー。
  • RAPPORT_EXPORT_VARIANS.txt：書き出しの報告書。
  • 場合により iiif/：IIIF 画像の HD コピー（必要なページすべてにコピーがある場合）。

画像は元の場所に置かれたままで、プロジェクトはそれを参照します（行は同期ファイルに含まれています）。フォルダーが空でない場合、ピボット伝本に複数の TEI 校訂本文がある場合、その TEI の対応付けが要再確認（資料が変更されています）の状態にある場合（対応付けをやり直してください。そのままでは <lb/> が別の行と対応してしまいます）、一つの伝本に IIIF 画像とローカル画像が混在している場合、またはファイルが見つからない場合は、書き出しは行われません。

Varians 用 JSON の書き出し

Varians 用 JSON を書き出す…は、既存の Varians プロジェクトに伝本を追加したり、伝本を更新したりするためのものです（ワークフロー B）。参照伝本（Varians プロジェクトのピボット伝本）を選んで確定し、空のフォルダーを選びます。そこに次のものが書き出されます：

  • validated/<シグラム>.json：伝本ごとに一つのファイル。承認済みの対応のみ。
  • working/<シグラム>.json：同じ内容に加えて、未承認の提案。
  • rapport_export.json：書き出しの集計と検査結果。

Varians は Varians-Synchro の状態を区別しません。そのことを承知のうえで試す場合を除き、validated/ を読み込んでください。書き出されるのは参照伝本との直接の同期だけで、第三の伝本を介した推定は行いません。書き出せる対応が一つもない伝本がある場合は、書き出しの前にその旨と原因が表示されます。

12. ファイル、バックアップ、トラブルシューティング

プロジェクトファイル

  • 作業内容はすべて .vsynch ファイルに入っています：伝本、取り込んだ ALTO/PAGE ファイルの内容、関連付け、無視した行、読み順、同期。元のファイルが変更されることはありません。
  • 保存は安全に行われます。ファイルは一度に置き換えられ、以前の版は <プロジェクト>.vsynch.bak に残されます。元に戻すには、この .bak を拡張子 .vsynch の新しい名前でコピーし、それを開きます。
  • 「名前を付けて保存」コマンドはありません。ある時点の版を残しておくには、.vsynch ファイルをコピーしてください。
  • 画像、ALTO/PAGE ファイル、TEI は .vsynch ファイルのフォルダーかそのサブフォルダーに置いてください。相対パスで保存されるので、そのフォルダーごとプロジェクトを移動・コピーできます（付属のサンプルと同じです）。ほかの場所にあるファイルは完全なパスで保存されます。
  • 他の人から受け取ったプロジェクト：.vsynch ファイルがそのフォルダーの外（.. を含むパス）やネットワーク共有上のファイルを指している場合、開くときにその一覧が表示され、読み込むかどうかを尋ねられます（既定は「いいえ」）。拒否すると、それらのファイルは見つからないものとして扱われ、保存時にはパスがそのまま残ります。許可すると、その答えはこのプロジェクトについて記憶されます。
  • 取り込み後にディスク上の ALTO/PAGE ファイルを変更しても、プロジェクトは変わりません。そのことは概要で報告されます。修正した領域分割を使うには、新しいファイルを取り込んでページに関連付けます（影響を受けるグループは失効します）。
  • ソフトウェアを閉じるとき、またプロジェクトを開くときや作成するときには、未保存の変更を保存するかどうか尋ねられます。

よくある問題

  • 「整列する前に、両方の伝本に ALTO ページを関連付けてください」：二つの伝本のどちらかに、行ファイルに関連付けられたページがまだ一つもありません（ステップ 2）。
  • IIIF 画像を利用できない：サーバーが応答していません。関連付けは失われていません。後で再試行するか、HD コピーをダウンロードしてください。
  • IIIF Manifest を利用できない：伝本の追加時に Manifest が応答しませんでした。URL は保持され、概要に表示されます。1 · 伝本の追加で伝本をクリックし、再試行を押してください。Manifest が応答したか、何ページあるかが表示されます。伝本を保存で結果が保持されます。
  • 画像上で輪郭がずれる：画像と ALTO/PAGE ファイルの縦横比が異なっています（ステータスバーに表示されます）。ファイルがその画像に確かに対応しているか確認してください。
  • 書き出しが拒否される：選んだフォルダーが空でないか、ピボット伝本の TEI の対応付けが要再確認の状態か、二つのシグラムが同じファイル名になります（古いプロジェクトの場合。基本概念を参照）。
  • Varians でピボット伝本の行が本文と対応しない：<lb edRef="#PIVOT"/> の数がピボット伝本の有効な行の数と異なっています（無視する行の指定漏れ、または <lb/> の不足）。Varians の写本の状態を診断…と、Varians-Synchro のTEI の対応付けが、食い違いを見つける助けになります。
  • Varians で、ファイルのリンクがピボット伝本のどの行にも対応しない：ピボット伝本の同期が同じ .vsynch プロジェクトに由来していません（ワークフロー Bを参照）。
  • Spyder を使う場合：run.py を実行してください。Spyder のコンソールを乱さないよう、ソフトウェアは別のプロセスで起動します。起動ログは ~/.varians_synchro/logs にあります。
