Varians-Synchro — Guide utilisateur

Varians-Synchro aligne, ligne par ligne, les manuscrits d’une même œuvre, à partir de leurs images et de la segmentation de leurs lignes (ALTO ou PAGE XML). Il prépare ainsi les fichiers de synchronisation qui permettent à Varians d’afficher chaque témoin à côté de l’édition, la bonne ligne du manuscrit en face du texte.

1. Présentation

Ce que fait Varians-Synchro

  • Il relie les lignes de deux manuscrits. Vous voyez les deux témoins côte à côte, avec le contour de chaque ligne, et vous dites quelles lignes de l’un correspondent à quelles lignes de l’autre. Une correspondance peut réunir plusieurs lignes de chaque côté.
  • Il propose, vous décidez. À partir de quelques repères que vous placez, il propose les correspondances intermédiaires d’après la quantité de texte ; vous les vérifiez sur les images et les validez.
  • Il travaille par rapport à un témoin pivot. Chaque autre témoin est aligné sur le pivot. Dans Varians, les lignes du pivot sont repérées dans l’édition par ses <lb/> ; les autres témoins suivent grâce à leur alignement sur le pivot.
  • Il exporte pour Varians un fichier de synchronisation (JSON) par témoin, ou un projet Varians complet, prêt à ouvrir.

Ce qu’il ne fait pas

  • Il ne transcrit pas et ne segmente pas les images : les lignes viennent d’un logiciel de reconnaissance (eScriptorium, Transkribus, Kraken…), sous forme de fichiers ALTO ou PAGE XML.
  • Il n’édite pas le texte TEI : c’est le rôle de Varians.
  • Il ne modifie jamais vos fichiers sources (images, ALTO, PAGE, TEI). Tout son travail est dans le fichier de projet .vsynch.

Ce qu’il faut pour commencer

  • Pour chaque témoin : ses images (fichiers locaux, ou un Manifest IIIF) et, pour chaque page à aligner, un fichier ALTO ou PAGE XML qui décrit ses lignes.
  • Facultativement, l’édition TEI du témoin pivot, si elle existe déjà.

La démarche en quatre étapes

La fenêtre principale suit quatre étapes, à gauche :

  1. 1 · Ajout des témoins : déclarer les manuscrits et leurs fichiers ;
  2. 2 · Associer les ressources : relier chaque image à son fichier de lignes, régler l’ordre des pages et les lignes à ignorer ;
  3. 3 · Aligner les témoins : aligner chaque témoin sur le pivot ;
  4. 4 · Finaliser : contrôler, puis exporter vers Varians.

Pensez à Enregistrer le projet après chaque séance de travail. L’aide s’ouvre à tout moment par Ouvrir le guide utilisateur ou F1.

2. Premier essai : le projet d’exemple

Le dossier demo_local_ALTO/, livré avec le logiciel, contient deux petits témoins fictifs, A et B, d’une page de trois lignes chacun, avec leurs fichiers ALTO. Leur texte est découpé différemment, comme dans deux vrais manuscrits. Dix minutes suffisent pour parcourir toute la démarche.

  1. Copiez le dossier demo_local_ALTO ailleurs : l’enregistrement modifie le fichier de projet.
  2. Cliquez sur Ouvrir .vsynch et choisissez exemple.vsynch dans la copie.
  3. Dans 1 · Ajout des témoins, cliquez sur le témoin A, cochez Définir ce témoin comme pivot pour l’alignement des témoins, puis Enregistrer le témoin.
  4. Dans 3 · Aligner les témoins, gardez A dans Pivot technique et B dans Témoin à aligner, puis cliquez sur Aligner les témoins.
  5. Dans la fenêtre de synchronisation, cliquez sur la première ligne de A, puis sur la première ligne de B, et faites Ctrl+Entrée (Associer les lignes). Faites de même pour les troisièmes lignes. Ces deux correspondances, en vert, sont vos repères.
  6. Cliquez sur Synchroniser entre repères (texte) : le logiciel propose de relier les deuxièmes lignes. Cliquez sur Enregistrer la sélection. La proposition apparaît en bleu pointillé : elle est à vérifier.
  7. En bas, avec le filtre À vérifier, choisissez la proposition dans la liste, vérifiez-la sur les images, puis cliquez sur Valider et suivant.
  8. Fermez la fenêtre de synchronisation et cliquez sur Enregistrer.
  9. Dans 4 · Finaliser, cliquez sur Créer un projet Varians pré-renseigné…, choisissez un dossier vide, puis ouvrez le project.xml créé dans Varians.

3. Parcours A : créer un nouveau projet Varians

Vous commencez une édition : aucun projet Varians n’existe encore. Varians-Synchro prépare le projet entier : témoins, images, synchronisations et, si vous l’avez, l’édition TEI du pivot.

Dans Varians-Synchro

  1. Créer le projet. Nouveau projet demande un nom, puis l’emplacement du fichier .vsynch, aussitôt enregistré.
  2. Déclarer les témoins. Dans 1 · Ajout des témoins, ajoutez chaque manuscrit avec Ajouter un témoin… : son sigle, ses images, ses fichiers ALTO/PAGE et, pour le pivot seulement, son édition TEI s’il y en a une. Choisissez le pivot (voir Notions clés) : le premier témoin ajouté l’est par défaut. Détails : Étape 1.
  3. Associer les images et les lignes. Dans 2 · Associer les ressources, vérifiez que chaque page est associée au bon fichier ALTO/PAGE et que les pages sont dans l’ordre de lecture. Indiquez les lignes à ignorer : celles qui sont hors du texte que vous éditez (début et fin d’un passage, titres courants, autre œuvre sur la même page). Détails : Étape 2.
  4. Aligner chaque témoin sur le pivot. Dans 3 · Aligner les témoins, choisissez le pivot dans Pivot technique, un autre témoin dans Témoin à aligner, et ouvrez Aligner les témoins. Placez des repères, laissez le logiciel proposer le reste, vérifiez et validez. Recommencez pour chaque témoin. Détails : La fenêtre de synchronisation.
  5. Enregistrer, puis, dans 4 · Finaliser, lancer Contrôler la cohérence du projet… et lire les avertissements.
  6. Créer le projet Varians. Créer un projet Varians pré-renseigné… écrit le projet dans un dossier vide. Il ne contient que les correspondances validées : validez donc tout ce qui doit compter avant cette étape. Détails : Projet Varians pré-renseigné.

Dans Varians

  1. Fichier → Ouvrir un projet…, puis le project.xml créé.
  2. Sans édition TEI, le projet reçoit une TEI vide, comme une nouvelle transcription dans Varians. Pour y préparer les pages et les lignes du pivot : Fichier → Paramètres du projet…, encadré Préparation de la transcription du témoin pivot, cochez Préparer les <pb/> du témoin pivot dans la TEI vide et, si vous le souhaitez, Générer aussi les <lb/> depuis ALTO, PAGE ou la synchronisation.
  3. Avec une édition TEI, elle doit contenir exactement un <lb edRef="#PIVOT"/> par ligne retenue du pivot, dans l’ordre de lecture : Varians fait correspondre la n-ième ligne du pivot au n-ième <lb/>. L’étape facultative Lier l’édition TEI de Varians-Synchro vous permet de le vérifier avant l’export.
  4. Contrôlez le résultat avec Affichage → État des témoins….

4. Parcours B : ajouter un témoin à un projet Varians existant

Votre projet Varians existe déjà et a été créé à partir d’un projet Varians-Synchro (ou la synchronisation de son pivot en vient). Vous voulez lui ajouter un nouveau manuscrit, synchronisé avec l’édition.

Le principe. Le fichier de synchronisation du nouveau témoin désigne les lignes du pivot par l’identifiant de leur page et leur rang dans cette page, tels que les connaît votre projet .vsynch. Il faut donc travailler dans le même projet .vsynch que celui qui a servi à créer le projet Varians, et ne pas toucher au pivot.

Dans Varians-Synchro

  1. Ouvrir .vsynch : ouvrez le projet qui a servi à créer le projet Varians.
  2. Dans 1 · Ajout des témoins, ajoutez le nouveau manuscrit avec Ajouter un témoin… (sigle, images, ALTO/PAGE). Donnez-lui le sigle qu’il aura dans Varians.
  3. Dans 2 · Associer les ressources, associez ses pages à leurs fichiers ALTO/PAGE et indiquez ses lignes à ignorer.
  4. Dans 3 · Aligner les témoins, gardez le pivot dans Pivot technique, choisissez le nouveau témoin dans Témoin à aligner, alignez et validez.
  5. Enregistrer.
  6. Dans 4 · Finaliser, Exporter JSON pour Varians… : choisissez le pivot comme témoin de référence et un dossier vide. Le fichier du nouveau témoin est validated/<sigle>.json (correspondances validées) ; working/<sigle>.json contient aussi les propositions non validées. Voir Exporter JSON pour Varians.
Ne modifiez pas le pivot (ses pages, leurs fichiers ALTO/PAGE, ses lignes ignorées, son ordre de lecture) : ses lignes changeraient de rang ou de nombre, et ne correspondraient plus aux <lb/> de l’édition. Si vous devez le faire, remplacez aussi la synchronisation du pivot dans Varians par validated/<pivot>.json, et vérifiez que le nombre de ses lignes est toujours celui de ses <lb/>.

Dans Varians

  1. Fichier → Paramètres du projet… ; dans la liste des témoins, Ajouter….
  2. Indiquez le sigle, les images (Source des images) et, dans Fichier de synchronisation (facultatif), le fichier validated/<sigle>.json. Cochez Copier la synchronisation dans le projet : le projet reste ainsi complet si vous le déplacez.
  3. Contrôlez avec Affichage → État des témoins… : le nouveau témoin doit avoir des liens valides vers le pivot.

Mettre à jour un témoin déjà présent

Après avoir complété l’alignement d’un témoin dans Varians-Synchro, exportez de nouveau, puis, dans Varians, donnez au témoin le nouveau fichier (Modifier… dans les paramètres du projet), ou remplacez son fichier dans le dossier alignments/ du projet. Affichage → Actualiser les synchronisations… (Ctrl+Maj+R) relit les fichiers sans rouvrir le projet.

Projet Varians qui ne vient pas de ce .vsynch. Les identifiants de pages diffèrent : Varians signale alors que les liens du fichier ne correspondent à aucune ligne du pivot. Il faut aussi remplacer la synchronisation du pivot par validated/<pivot>.json, avec le même nombre de lignes que ses <lb/>.

5. Notions clés

NotionCe qu’elle désigne
Témoin, sigleUn manuscrit (ou une édition ancienne). Le sigle est son identifiant : il ne peut plus être changé après l’enregistrement du témoin, et ne doit contenir ni point, ni /, ni \ pour que l’export soit possible. Gardez celui du projet Varians.
Témoin pivotLe témoin de référence du projet : les autres sont alignés sur lui, et Varians le suit par ses <lb/>. Ce choix est technique : il ne préjuge ni du stemma ni du manuscrit de base de l’édition. Le premier témoin ajouté est pivot par défaut ; pour en changer, cochez la case du pivot dans la fiche d’un autre témoin. Le menu Pivot technique de l’étape 3 choisit seulement le témoin de gauche à aligner, sans changer le pivot du projet.
Ligne physiqueUne ligne décrite par le fichier ALTO/PAGE d’une page. Elle est identifiée par sa page et son rang dans ce fichier. Le contenu du fichier est copié dans le projet à l’import.
Ligne ignorée (périmètre)Une ligne hors du texte étudié. Elle vaut pour le témoin dans tout le projet : elle est exclue des calculs, de la liaison TEI et des exports. Ignorer une ligne déjà liée retire ses liens, dans toutes les paires, après confirmation.
Groupe (correspondance)Des lignes du témoin de gauche reliées à des lignes du témoin de droite : 1↔1, 1↔n ou n↔m. Une ligne appartient au plus à un groupe par paire.
État d’un groupevalidated (validé), uncertain (incertain) ou proposed (proposé). La liste des groupes les affiche tels quels. Le filtre À vérifier réunit les groupes non validés.
RepèreUne correspondance validée qui sert d’appui aux propositions. Les repères doivent se suivre dans le même ordre dans les deux témoins ; il en faut au moins deux.
Absence confirméeDes lignes d’un témoin qui n’ont pas d’équivalent dans l’autre (omission, lacune). Elle vaut pour une paire, apparaît en rouge et ne produit aucun lien à l’export.
Ligne non synchroniséeUne ligne retenue qui n’appartient encore à aucun groupe dans la paire (en violet).
Groupe périméUn groupe dont une ligne a changé : en général, la page a reçu un autre fichier ALTO/PAGE. Il n’est jamais supprimé, mais il est exclu des repères, des calculs et des exports jusqu’à ce que vous le revalidiez ou le dissociiez.
ProtectionLes groupes manuels et les groupes validés ne sont jamais remplacés par un calcul. Seules les propositions automatiques non validées peuvent l’être.

6. Étape 1 : ajout des témoins

Ajouter un témoin… ouvre la fiche d’un nouveau témoin ; un clic sur un témoin de la liste (ou sur l’une de ses ressources) ouvre sa fiche pour la compléter. La liste montre, pour chaque témoin, ses ressources et leur état (pages associées, lignes importées, liaison TEI).

La fiche du témoin

  • Sigle et Description. Le sigle n’est plus modifiable une fois le témoin enregistré.
  • Définir ce témoin comme pivot pour l’alignement des témoins.
  • Quatre groupes de ressources, chacun avec Ajouter… :
    • Images locales : les images sont triées par nom (« 2 » avant « 10 ») ;
    • Manifest IIIF : l’adresse du Manifest ; s’il ne répond pas, l’adresse est gardée, avec l’état indisponible ;
    • Fichiers ALTO/PAGE-XML : le format est reconnu d’après le contenu ;
    • Édition TEI XML : facultative, utile pour le pivot.
  • Supprimer retire seulement une ressource ajoutée pendant cette ouverture de la fiche : une ressource déjà enregistrée reste dans le projet, pour ne pas casser ses associations.
  • Associer automatiquement les images et les ALTO/PAGE propose tout de suite les associations des pages (voir ci-dessous).
  • Enregistrer le témoin applique tout d’un bloc ; Annuler ne change rien au projet.

7. Étape 2 : associer les ressources

Quatre opérations, chacune pour un témoin à choisir :

Pages, ordre et fichiers de lignes

Gérer les images, leur ordre et les associations ALTO/PAGE… montre les pages du témoin, avec leur miniature et leur fichier de lignes.

  • Ordre de lecture : glissez les pages, ou utilisez Monter, Descendre, Inverser l’ordre.
  • Associer ALTO/PAGE donne à la page choisie un fichier de lignes. Si elle en avait déjà un, le logiciel dit combien de groupes seront touchés : ils deviendront périmés (voir Groupes périmés).
  • Afficher page (ou un double-clic) montre la page et ses lignes.
  • Copies HD des images IIIF : Télécharger les images IIIF sélectionnées en HD… enregistre les images choisies dans un dossier vide ; Rattacher un lot HD déjà téléchargé… retrouve un lot précédent. Le projet Varians utilise ces copies si toutes les pages utiles en ont une.
  • HTR externe (facultatif) : Exporter pour HTR enregistre les images IIIF choisies dans un ZIP pour un logiciel de reconnaissance ; Réimporter HTR associe ensuite les fichiers ALTO/PAGE obtenus, par leur nom.

Ces changements sont faits directement : fermez avec Fermer, puis enregistrez le projet.

Associer automatiquement

Associer automatiquement les images et les ALTO/PAGE propose un fichier de lignes pour chaque page qui n’en a pas encore : d’abord d’après les noms et les références d’image (Nom unique), puis, pour des images locales en nombre égal, d’après l’ordre naturel des noms. Contrôlez surtout ces dernières : un décalage se répercute sur toute la série. Un même fichier proposé pour deux pages est signalé en rouge. Appliquer les associations n’écrase aucune association existante.

Lignes à ignorer (périmètre)

Définir les lignes à ignorer sur les images du témoin… : sélectionnez sur les images les lignes hors du texte étudié, même sur plusieurs pages, puis Ignorer les lignes sélectionnées (ou Réintégrer les lignes sélectionnées). Conserver le périmètre applique ; Annuler ne change rien. Le même réglage existe dans la fenêtre de synchronisation (Périmètre ▾).

Lier l’édition TEI (facultatif)

Lier l’édition TEI aux lignes ALTO/PAGE… rapproche les <lb edRef="#SIGLE"/> d’une édition TEI des lignes retenues du témoin, dans l’ordre de lecture. Les nombres doivent être égaux : la fenêtre les compare et signale ce qui bloque (lignes à ignorer oubliées, leçons ambiguës d’un apparat). Vérifiez quelques lignes, notamment avec Début et Fin, sur le texte et l’image recadrée, puis Confirmer les liaisons.

La liaison n’est pas nécessaire à l’export : elle sert à vérifier que le nombre de lignes du pivot correspond bien à ses <lb/>, et fait afficher le texte TEI à la place du texte HTR dans la fenêtre de synchronisation. Elle passe à à revérifier (sources modifiées) si l’édition, le périmètre, l’ordre ou la segmentation changent.

8. Étape 3 : aligner les témoins

Choisissez le témoin de gauche dans Pivot technique (en général le pivot du projet) et l’autre témoin dans Témoin à aligner, puis cliquez sur Aligner les témoins. Il n’existe qu’une synchronisation par paire : l’ouvrir dans l’autre sens rouvre la même, avec le même témoin à gauche.

Sous le bouton, la liste des paires déjà alignées montre leur avancement (nombre de groupes, lignes reliées de chaque côté). Un double-clic sur une paire, ou Entrée, rouvre sa synchronisation ; un simple clic la choisit dans les deux menus.

Pour l’export vers Varians, chaque témoin doit être aligné directement sur le pivot : un alignement B↔C ne sert pas à l’export si le pivot est A.

9. La fenêtre de synchronisation

Les deux témoins sont côte à côte, le témoin de référence à gauche. Les contours des lignes sont colorés selon leur état. Tout le travail se fait en mémoire : enregistrez le projet dans la fenêtre principale après l’avoir fermée. F1 ouvre ici cette section de l’aide.

La méthode conseillée

  1. Placer des repères. Reliez quelques lignes sûres, au début, à la fin, et aux endroits où les manuscrits divergent (changement de colonne, lacune, ajout) : sélectionnez la ou les lignes à gauche et à droite, puis Associer les lignes (Ctrl+Entrée). Un groupe créé ainsi est manuel et validé (vert plein).
  2. Faire proposer le reste. Synchroniser entre repères (texte) calcule, entre deux repères, les correspondances les plus probables d’après la quantité de texte de chaque ligne. Une fenêtre montre les propositions : gardez celles qui conviennent, puis Enregistrer la sélection. Elles sont enregistrées à vérifier (bleu pointillé).
  3. Vérifier et valider. En bas, choisissez le filtre À vérifier et parcourez les groupes avec Suivant ▶ (F8) et ◀ Précédent (Maj+F8). Le groupe choisi apparaît en rose sur les deux images. Valider et suivant (Alt+V) le valide et passe au suivant.
  4. Corriger. Pour ajouter une ligne à un groupe, sélectionnez-la avec une ligne du groupe et faites Associer les lignes. Pour en retirer, sélectionnez-la et faites Dissocier. Un groupe corrigé devient manuel (vert) et protégé.
  5. Traiter les absences (voir ci-dessous), puis fermer et enregistrer.

Sélectionner les lignes

  • Un clic sur une ligne la sélectionne (orange) et remplace la sélection du témoin, sur toutes ses pages.
  • Ctrl+clic ajoute ou retire une ligne ; Maj+clic sélectionne une suite de lignes dans l’ordre de lecture du témoin, d’une page à l’autre.
  • Un clic sur une ligne déjà reliée montre en rose ses lignes correspondantes dans l’autre témoin (en changeant de page s’il le faut). Le rose n’est jamais une sélection.
  • Molette : zoom ; glisser : déplacer l’image ; double-clic : zoom sur la ligne. Adapter montre la page entière.
  • Texte HTR affiche le texte des lignes sous l’image (le texte TEI si une liaison TEI est valide). Cadres lignes masque ou montre les contours ; Effacer sélection vide la sélection.

Cadres visibles limite l’affichage aux Lignes non synchronisées ou aux Synchronisations automatiques à vérifier, pour repérer ce qui reste à faire.

La liste des groupes

En bas, Vérification filtre les groupes : Tous les groupes, À vérifier, Validés, Absences confirmées, Périmés. Chaque groupe y est décrit par son état et ses lignes, nommées page:rang (libellé de la page, rang de la ligne). On peut en sélectionner plusieurs (Ctrl, Maj) pour Valider la sélection….

Recalcul local… refait les propositions du seul intervalle qui suit le repère choisi, par exemple après avoir ajouté un repère.

Absences confirmées

Quand des lignes d’un témoin n’ont pas d’équivalent dans l’autre, sélectionnez-les d’un seul côté, puis Autres opérations → Confirmer l’absence des lignes sélectionnées (Ctrl+Maj+A). Elles cessent d’être « non synchronisées » et apparaissent en rouge. Retirer les absences sélectionnées dans la liste annule une absence choisie avec le filtre Absences confirmées.

Groupes périmés

Donner à une page un autre fichier ALTO/PAGE (une segmentation corrigée) peut changer ses lignes. Avant le remplacement, le logiciel dit combien de groupes citent ces lignes ; après, ceux dont une ligne a changé sont marqués « [périmé] ». Le filtre Périmés les liste. Après vérification sur les images, Revalider… les rétablit ; sinon, dissociez-les. L’ordre de lecture corrigé de la page est remis à zéro.

Autres opérations

  • Supprimer le(s) groupe(s) sélectionné(s) dans la liste et Marquer incertain agissent sur les groupes choisis dans la liste.
  • Proposer via HTR (facultatif) cherche des correspondances d’après la ressemblance du texte HTR des lignes. Rien n’est présélectionné : choisissez les propositions à garder.
  • Ordre de lecture et intervalles… corrige l’ordre des pages, des régions (colonnes) et des lignes d’un témoin, quand la segmentation ne le donne pas correctement, et montre les intervalles entre repères.
  • Ancienne interpolation géométrique (compatibilité) et Ancien complément des lignes résiduelles (compatibilité) sont d’anciennes méthodes, gardées pour les projets qui les utilisaient.

L’onglet Vue textuelle (facultative) montre les lignes des deux témoins en texte. Les commandes agissent sur la sélection de l’onglet affiché.

10. Étape 4 : finaliser et exporter

Actualiser le bilan résume les témoins et les synchronisations, et signale les lignes modifiées ou les fichiers introuvables.

Contrôler la cohérence

Contrôler la cohérence du projet… vérifie le projet sans rien modifier : lignes retenues et pages associées de chaque témoin, groupes validés et absences de chaque paire, références manquantes ou périmées, fichiers introuvables. Faites-le avant chaque export.

Projet Varians pré-renseigné

Créer un projet Varians pré-renseigné… écrit, dans un dossier vide, un projet que Varians ouvre tel quel :

  • project.xml : les témoins, leurs images (Manifest IIIF, ou chemins des images locales) et le pivot ;
  • xml/edition.xml : l’édition TEI du pivot, ou une TEI vide s’il n’en a pas ;
  • alignments/<sigle>.json : la synchronisation de chaque témoin, correspondances validées seulement ;
  • rendering/, i18n/, web_output/ : les dossiers habituels d’un projet Varians ;
  • RAPPORT_EXPORT_VARIANS.txt : le compte rendu de l’export ;
  • éventuellement iiif/ : les copies HD des images IIIF, si toutes les pages utiles en ont une.

Les images restent à leur place : le projet pointe vers elles (les lignes sont dans les fichiers de synchronisation). L’export est refusé si le dossier n’est pas vide, si un sigle contient un point, / ou \, si le pivot a plusieurs éditions TEI, si un témoin mélange images IIIF et locales, ou si un fichier est introuvable.

Exporter JSON pour Varians

Exporter JSON pour Varians… sert à ajouter ou mettre à jour des témoins dans un projet Varians existant (Parcours B). Choisissez le témoin de référence (le pivot du projet Varians), confirmez, puis choisissez un dossier vide. Le logiciel y écrit :

  • validated/<sigle>.json : un fichier par témoin, correspondances validées seulement ;
  • working/<sigle>.json : les mêmes, plus les propositions non validées ;
  • rapport_export.json : les comptes et les contrôles de l’export.

Varians ne connaît pas les états de Varians-Synchro : importez validated/, sauf pour un essai en connaissance de cause. Seules les synchronisations directes avec le témoin de référence sont exportées, sans déduction par un troisième témoin. Si un témoin n’a aucune correspondance exportable, le logiciel le dit avant l’export, avec la cause.

11. Format des fichiers de synchronisation (JSON)

Un fichier par témoin, en UTF-8, au format tei-manuscript-alignment, version 1, que lit Varians. Le fichier du pivot décrit ses lignes ; celui de chaque autre témoin décrit les siennes et les relie aux lignes du pivot.

Ce que Varians en fait

  • Les lignes du fichier du pivot, dans l’ordre du fichier, correspondent une à une aux <lb edRef="#PIVOT"/> de l’édition : la première ligne au premier <lb/>, et ainsi de suite. Varians vérifie que les nombres sont égaux.
  • Une clé du pivot est id_de_page::rang : elle reste valable tant que la page garde son identifiant et son fichier ALTO/PAGE. C’est pourquoi le nouveau témoin d’un projet existant doit être aligné dans le même projet .vsynch (Parcours B).
  • Quand le texte arrive à une ligne du pivot, Varians montre, dans chaque autre témoin, la ou les lignes dont les base_keys la désignent.

12. Fichiers, sauvegardes et dépannage

Le fichier de projet

  • Tout le travail est dans le fichier .vsynch : témoins, contenu des fichiers ALTO/PAGE importés, associations, lignes ignorées, ordre de lecture, synchronisations. Les fichiers sources ne sont jamais modifiés.
  • L’enregistrement est sûr : le fichier est remplacé d’un seul coup, et la version précédente est gardée dans <projet>.vsynch.bak. Pour revenir en arrière, copiez ce .bak sous un nouveau nom en .vsynch et ouvrez-le.
  • Il n’y a pas de commande « Enregistrer sous » : pour garder une version, copiez le fichier .vsynch.
  • Un projet dont les chemins sont relatifs (comme l’exemple livré) s’ouvre depuis n’importe quel dossier ; à l’enregistrement, les chemins sont écrits en entier.
  • Modifier un fichier ALTO/PAGE sur le disque après l’import ne change pas le projet ; le bilan le signale. Pour une segmentation corrigée, importez le nouveau fichier et associez-le à la page (les groupes touchés deviennent périmés).
  • Fermer le logiciel, ouvrir ou créer un projet propose d’enregistrer les modifications en cours.

Problèmes fréquents

  • « Associez des pages ALTO aux deux témoins avant de synchroniser » : un des deux témoins n’a encore aucune page associée à un fichier de lignes (Étape 2).
  • Image IIIF indisponible : le serveur ne répond pas ; les associations ne sont pas perdues. Réessayez plus tard, ou téléchargez des copies HD.
  • Cadres décalés sur l’image : l’image et le fichier ALTO/PAGE n’ont pas les mêmes proportions (la barre d’état le signale) ; vérifiez que le fichier correspond bien à cette image.
  • Export refusé : le dossier choisi n’est pas vide, ou un sigle contient un point, / ou \.
  • Dans Varians, les lignes du pivot ne correspondent pas au texte : le nombre de <lb edRef="#PIVOT"/> diffère du nombre de lignes retenues du pivot (lignes à ignorer oubliées, ou <lb/> manquants). État des témoins… dans Varians et la liaison TEI de Varians-Synchro aident à trouver l’écart.
  • Dans Varians, les liens du fichier ne correspondent à aucune ligne du pivot : la synchronisation du pivot ne vient pas du même projet .vsynch (voir Parcours B).
  • Avec Spyder : lancez run.py ; le logiciel s’ouvre dans un processus à part, pour ne pas troubler la console de Spyder. Le journal de démarrage est dans ~/.varians_synchro/logs.
