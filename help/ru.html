Varians-Synchro — Руководство пользователя

Varians-Synchro построчно выравнивает рукописи одного произведения по их изображениям и сегментации строк (ALTO или PAGE XML). Так он готовит файлы синхронизации, благодаря которым Varians показывает каждого свидетеля рядом с изданием: нужная строка рукописи стоит напротив текста.

1. Обзор

Что делает Varians-Synchro

  • Он связывает строки двух рукописей. Вы видите двух свидетелей рядом, с контуром каждой строки, и указываете, какие строки одного соответствуют каким строкам другого. Одно соответствие может объединять несколько строк с каждой стороны.
  • Он предлагает, вы решаете. По нескольким опорным точкам, которые ставите вы, он предлагает промежуточные соответствия исходя из объёма текста; вы проверяете их по изображениям и подтверждаете.
  • Он работает относительно опорного свидетеля. Каждый другой свидетель выравнивается по опорному. В Varians строки опорного свидетеля отмечены в издании его элементами <lb/>; остальные свидетели следуют за ним благодаря выравниванию по опорному.
  • Он экспортирует для Varians файл синхронизации (JSON) для каждого свидетеля или полный проект Varians, готовый к открытию.

Чего он не делает

  • Он не транскрибирует и не сегментирует изображения: строки поступают из программы распознавания (eScriptorium, Transkribus, Kraken…) в виде файлов ALTO или PAGE XML.
  • Он не редактирует текст TEI: это задача Varians.
  • Он никогда не изменяет ваши исходные файлы (изображения, ALTO, PAGE, TEI). Вся его работа хранится в файле проекта .vsynch.

Что нужно для начала

  • Для каждого свидетеля: его изображения (локальные файлы или манифест IIIF) и для каждой выравниваемой страницы файл ALTO или PAGE XML с описанием её строк.
  • По желанию — издание TEI опорного свидетеля, если оно уже существует.

Работа в четыре шага

Главное окно ведёт через четыре шага, перечисленных слева:

  1. 1 · Добавление свидетелей: объявить рукописи и их файлы;
  2. 2 · Связывание ресурсов: связать каждое изображение с его файлом строк, задать порядок страниц и игнорируемые строки;
  3. 3 · Выравнивание свидетелей: выровнять каждого свидетеля по опорному;
  4. 4 · Завершение: проверить, затем экспортировать в Varians.

Не забывайте нажимать Сохранить после каждого сеанса работы над проектом. Справка открывается в любой момент кнопкой Открыть руководство пользователя или клавишей F1.

2. Первый опыт: пример проекта

Папка demo_local_ALTO/, поставляемая с программой, содержит двух небольших вымышленных свидетелей, A и B, по одной странице из трёх строк, вместе с их файлами ALTO. Текст в них разбит на строки по-разному, как в двух настоящих рукописях. Чтобы пройти весь путь, достаточно десяти минут.

  1. Скопируйте папку demo_local_ALTO в другое место: при сохранении файл проекта изменяется.
  2. Нажмите Открыть .vsynch и выберите exemple.vsynch в копии.
  3. В разделе 1 · Добавление свидетелей список свидетелей показывает, что A — опорный свидетель («A — A · Опорный»): по нему будет выровнен B. Чтобы выбрать другого опорного свидетеля, щёлкните свидетеля, отметьте Назначить этого свидетеля опорным для выравнивания, затем нажмите Сохранить свидетеля.
  4. В разделе 3 · Выравнивание свидетелей оставьте A в поле Технический опорный свидетель и B в поле Сравниваемый свидетель, затем нажмите Выровнять свидетелей.
  5. В окне синхронизации щёлкните первую строку A, затем первую строку B и нажмите Ctrl+Enter (Связать строки). Сделайте то же самое для третьих строк. Эти два соответствия, зелёного цвета, — ваши опорные точки.
  6. Нажмите Выровнять между опорными точками (текст): программа предложит связать вторые строки. Нажмите Сохранить выделенное. Предложение показано синим пунктиром: его нужно проверить.
  7. Внизу, с фильтром На проверку, выберите предложение в списке, проверьте его по изображениям, затем нажмите Подтвердить и далее.
  8. Закройте окно синхронизации и нажмите Сохранить.
  9. В разделе 4 · Завершение нажмите Создать предварительно заполненный проект Varians…, выберите пустую папку, затем откройте созданный project.xml в Varians.

3. Сценарий A: создать новый проект Varians

Вы начинаете издание: проекта Varians ещё нет. Varians-Synchro готовит весь проект: свидетелей, изображения, синхронизации и, если оно у вас есть, издание TEI опорного свидетеля.

В Varians-Synchro

  1. Создайте проект. Новый проект запрашивает название, затем место для файла .vsynch, который сразу же сохраняется.
  2. Объявите свидетелей. В разделе 1 · Добавление свидетелей добавьте каждую рукопись кнопкой Добавить свидетеля…: её сиглу, изображения, файлы ALTO/PAGE и — только для опорного свидетеля — его издание TEI, если оно есть. Выберите опорного свидетеля (см. Основные понятия): по умолчанию им становится первый добавленный свидетель. Подробнее: Шаг 1.
  3. Свяжите изображения и строки. В разделе 2 · Связывание ресурсов проверьте, что каждая страница связана с нужным файлом ALTO/PAGE и что страницы идут в порядке чтения. Укажите игнорируемые строки: те, что лежат вне издаваемого текста (начало и конец отрывка, колонтитулы, другое произведение на той же странице). Подробнее: Шаг 2.
  4. Выровняйте каждого свидетеля по опорному. В разделе 3 · Выравнивание свидетелей выберите опорного свидетеля в поле Технический опорный свидетель, другого свидетеля — в поле Сравниваемый свидетель и откройте Выровнять свидетелей. Поставьте опорные точки, дайте программе предложить остальное, проверьте и подтвердите. Повторите для каждого свидетеля. Подробнее: Окно синхронизации.
  5. Сохраните проект, затем в разделе 4 · Завершение запустите Проверить согласованность проекта… и прочитайте предупреждения.
  6. Создайте проект Varians. Создать предварительно заполненный проект Varians… записывает проект в пустую папку. В него входят только подтверждённые соответствия: поэтому до этого шага подтвердите всё, что должно учитываться. Подробнее: Предварительно заполненный проект Varians.

В Varians

  1. Файл → Открыть проект…, затем созданный project.xml.
  2. Без издания TEI проект получает пустое издание TEI, как при новой транскрипции в Varians. Чтобы подготовить в нём страницы и строки опорного свидетеля: Файл → Параметры проекта…, блок Подготовка транскрипции опорного свидетеля; отметьте Создать метки <pb/> опорного свидетеля в пустом TEI и, при желании, Также создать метки <lb/> по ALTO, PAGE или данным синхронизации.
  3. С изданием TEI: оно должно содержать ровно один <lb edRef="#PIVOT"/> на каждую активную строку опорного свидетеля, в порядке чтения: Varians сопоставляет n-ю строку опорного свидетеля с n-м <lb/>. Необязательный шаг Связать издание TEI в Varians-Synchro позволяет проверить это до экспорта.
  4. Проверьте результат: Вид → Диагностика рукописей….

4. Сценарий B: добавить свидетеля в существующий проект Varians

Ваш проект Varians уже существует и был создан из проекта Varians-Synchro (или оттуда взята синхронизация его опорного свидетеля). Вы хотите добавить в него новую рукопись, синхронизированную с изданием.

Принцип. Файл синхронизации нового свидетеля обозначает строки опорного свидетеля идентификатором их страницы и порядковым номером на этой странице — так, как их знает ваш проект .vsynch. Поэтому нужно работать в том же проекте .vsynch, из которого был создан проект Varians, и не трогать опорного свидетеля.

В Varians-Synchro

  1. Открыть .vsynch: откройте проект, из которого был создан проект Varians.
  2. В разделе 1 · Добавление свидетелей добавьте новую рукопись кнопкой Добавить свидетеля… (сигла, изображения, ALTO/PAGE). Дайте свидетелю ту сиглу, под которой он будет в Varians.
  3. В разделе 2 · Связывание ресурсов свяжите его страницы с их файлами ALTO/PAGE и укажите его игнорируемые строки.
  4. В разделе 3 · Выравнивание свидетелей оставьте опорного свидетеля в поле Технический опорный свидетель, выберите нового свидетеля в поле Сравниваемый свидетель, выровняйте и подтвердите.
  5. Сохранить.
  6. В разделе 4 · Завершение — Экспортировать JSON для Varians…: выберите опорного свидетеля в качестве свидетеля отсчёта и пустую папку. Файл нового свидетеля — validated/<сигла>.json (подтверждённые соответствия); working/<сигла>.json содержит также неподтверждённые предложения. См. Экспортировать JSON для Varians.
Не изменяйте опорного свидетеля (его страницы, их файлы ALTO/PAGE, его игнорируемые строки, его порядок чтения): у его строк изменились бы номера или число, и они перестали бы соответствовать <lb/> издания. Если это всё же необходимо, замените в Varians и синхронизацию опорного свидетеля файлом validated/<pivot>.json и проверьте, что число его строк по-прежнему равно числу его <lb/>.

В Varians

  1. Файл → Параметры проекта…; в списке свидетелей — Добавить….
  2. Укажите сиглу, изображения (Источник изображений) и в поле Файл синхронизации (необязательно) — файл validated/<сигла>.json. Отметьте Копировать синхронизацию в проект: так проект останется полным, если вы его переместите.
  3. Проверьте результат: Вид → Диагностика рукописей…. У нового свидетеля должны быть действительные связи с опорным.

Обновление свидетеля, уже включённого в проект

Дополнив выравнивание свидетеля в Varians-Synchro, снова выполните экспорт, затем в Varians укажите для свидетеля новый файл (Изменить… в параметрах проекта) или замените его файл в папке alignments/ проекта. Вид → Обновить синхронизацию… (Ctrl+Shift+R) перечитывает файлы без повторного открытия проекта.

Проект Varians, созданный не из этого .vsynch. Идентификаторы страниц различаются, и Varians сообщает, что связи файла не соответствуют ни одной строке опорного свидетеля. В этом случае нужно также заменить синхронизацию опорного свидетеля файлом validated/<pivot>.json, в котором столько же строк, сколько у опорного свидетеля <lb/>.

5. Основные понятия

ПонятиеЧто оно обозначает
Свидетель, сиглаРукопись (или старое издание). Сигла — её идентификатор: после сохранения свидетеля её уже нельзя изменить, а чтобы экспорт был возможен, в ней не должно быть ни точки, ни /, ни \. Используйте ту же сиглу, что и в проекте Varians.
Опорный свидетельСвидетель отсчёта проекта: остальные выравниваются по нему, а Varians следует за ним по его <lb/>. Этот выбор технический: он ничего не предрешает ни о стемме, ни об основной рукописи издания. По умолчанию опорным становится первый добавленный свидетель; чтобы сменить его, отметьте флажок опорного свидетеля в карточке другого свидетеля. Меню Технический опорный свидетель на шаге 3 лишь выбирает левого свидетеля для выравнивания и не меняет опорного свидетеля проекта.
Физическая строкаСтрока, описанная в файле ALTO/PAGE страницы. Она определяется своей страницей и порядковым номером в этом файле. Содержимое файла копируется в проект при импорте.
Игнорируемая строка (объём)Строка вне изучаемого текста. Она игнорируется для данного свидетеля во всём проекте: исключается из расчётов, из привязки TEI и из экспорта. Если игнорировать уже связанную строку, её связи удаляются во всех парах (после подтверждения).
Группа (соответствие)Строки левого свидетеля, связанные со строками правого: 1↔1, 1↔n или n↔m. В каждой паре строка входит не более чем в одну группу.
Состояние группыvalidated (подтверждённая), uncertain (неуверенная) или proposed (предложенная). Список групп показывает состояния именно в таком виде. Фильтр На проверку объединяет неподтверждённые группы.
Опорная точкаПодтверждённое соответствие, на которое опираются предложения. Опорные точки должны идти в одном и том же порядке у обоих свидетелей; их нужно не меньше двух.
Подтверждённое отсутствиеСтроки одного свидетеля, у которых нет соответствия в другом (пропуск, лакуна). Оно действует в пределах пары, показывается красным и при экспорте не создаёт никакой связи.
Несвязанная строкаАктивная строка, которая в данной паре ещё не входит ни в одну группу (фиолетовая).
Устаревшая группаГруппа, одна из строк которой изменилась: обычно странице назначили другой файл ALTO/PAGE. Такая группа никогда не удаляется, но исключается из опорных точек, расчётов и экспорта, пока вы не подтвердите её заново или не разъедините.
ЗащитаРучные и подтверждённые группы никогда не заменяются результатом расчёта. Заменить можно только неподтверждённые автоматические предложения.

6. Шаг 1: добавление свидетелей

Добавить свидетеля… открывает карточку нового свидетеля; щелчок по свидетелю в списке (или по одному из его ресурсов) открывает его карточку, чтобы её дополнить. Для каждого свидетеля список показывает его ресурсы и их состояние (связанные страницы, импортированные строки, привязка TEI).

Карточка свидетеля

  • Сигла и Описание. После сохранения свидетеля сиглу изменить нельзя.
  • Назначить этого свидетеля опорным для выравнивания.
  • Четыре группы ресурсов, у каждой кнопка Добавить…:
    • Локальные изображения: изображения сортируются по имени («2» перед «10»);
    • Манифест IIIF: адрес манифеста; если он не отвечает, адрес сохраняется с пометкой «недоступен»;
    • Файлы ALTO/PAGE-XML: формат определяется по содержимому;
    • Издание TEI XML: необязательно, полезно для опорного свидетеля.
  • Удалить убирает только ресурс, добавленный за время текущего открытия карточки: уже сохранённый ресурс остаётся в проекте, чтобы не нарушить его связи.
  • Автоматическое связывание изображений и ALTO/PAGE сразу предлагает связи страниц (см. ниже).
  • Сохранить свидетеля применяет всё одной операцией; Отмена ничего не меняет в проекте.

7. Шаг 2: связывание ресурсов

Здесь четыре операции, каждая — для выбранного вами свидетеля:

Страницы, порядок и файлы строк

Управлять изображениями, их порядком и связями ALTO/PAGE… показывает страницы свидетеля с их миниатюрами и файлами строк.

  • Порядок чтения: перетаскивайте страницы или используйте Выше, Ниже, Обратный порядок.
  • Связать ALTO/PAGE назначает выбранной странице файл строк. Если файл у неё уже был, программа сообщает, сколько групп это затронет: они станут устаревшими (см. Устаревшие группы).
  • Показать страницу (или двойной щелчок) показывает страницу и её строки.
  • HD-копии изображений IIIF: Скачать выбранные изображения IIIF в HD… сохраняет выбранные изображения в пустую папку; Подключить ранее скачанный HD-набор… находит предыдущий набор. Проект Varians использует эти копии, если они есть у всех нужных страниц.
  • Внешняя обработка HTR (необязательно): Экспортировать для HTR сохраняет выбранные изображения IIIF в ZIP-архив для программы распознавания; Повторно импортировать HTR затем связывает полученные файлы ALTO/PAGE по их именам.

Эти изменения применяются сразу: закройте окно кнопкой Закрыть, затем сохраните проект.

Автоматическое связывание

Автоматическое связывание изображений и ALTO/PAGE предлагает файл строк для каждой страницы, у которой его ещё нет: сначала по именам и ссылкам на изображения (Уникальное имя), затем — если все оставшиеся страницы являются локальными изображениями и несвязанных страниц ALTO/PAGE осталось ровно столько же, — сопоставляя их в естественном порядке имён файлов. Особенно внимательно проверяйте последние: сдвиг распространяется на всю серию. Если один и тот же файл предложен для двух страниц, он отмечается красным. Применить связи не перезаписывает ни одной существующей связи.

Игнорируемые строки (объём)

Указать игнорируемые строки на изображениях свидетеля…: выделите на изображениях строки вне изучаемого текста, в том числе на нескольких страницах, затем нажмите Игнорировать выбранные строки (или Вернуть выбранные строки). Сохранить объём применяет изменения; Отмена ничего не меняет. Та же настройка есть в окне синхронизации (Объём ▾).

Связать издание TEI (необязательно)

Связать издание TEI со строками ALTO/PAGE… сопоставляет элементы <lb edRef="#СИГЛА"/> издания TEI с активными строками свидетеля в порядке чтения. Их число должно совпадать: окно сравнивает его и сообщает, что мешает привязке (забытые игнорируемые строки, неоднозначные чтения аппарата). Проверьте несколько строк по тексту и по кадрированному изображению, в частности кнопками Начало и Конец, затем нажмите Подтвердить связи.

Для экспорта привязка не нужна: она позволяет проверить, что число строк опорного свидетеля действительно соответствует числу его <lb/>, а в окне синхронизации благодаря ей показывается текст TEI вместо текста HTR. Её состояние меняется на требуется проверка (источники изменены), если изменились издание, объём, порядок или сегментация.

8. Шаг 3: выравнивание свидетелей

Выберите левого свидетеля в поле Технический опорный свидетель (обычно это опорный свидетель проекта) и другого свидетеля в поле Сравниваемый свидетель, затем нажмите Выровнять свидетелей. Для каждой пары существует только одна синхронизация: если открыть её в обратном направлении, откроется та же самая, с тем же свидетелем слева.

Под кнопкой список уже выровненных пар показывает, насколько продвинулась работа (число групп, связанные строки с каждой стороны). Двойной щелчок по паре или Enter снова открывает её синхронизацию; одинарный щелчок выбирает её в обоих меню.

Для экспорта в Varians каждый свидетель должен быть выровнен непосредственно по опорному: если опорный свидетель — A, выравнивание B↔C при экспорте не используется.

9. Окно синхронизации

Два свидетеля показаны рядом, свидетель отсчёта — слева. Контуры строк окрашены в зависимости от их состояния. Вся работа ведётся в памяти: закрыв окно, сохраните проект в главном окне. F1 открывает здесь этот раздел справки.

Рекомендуемый порядок работы

  1. Поставьте опорные точки. Свяжите несколько надёжных строк — в начале, в конце и там, где рукописи расходятся (смена столбца, лакуна, добавление): выделите одну или несколько строк слева и справа, затем выполните Связать строки (Ctrl+Enter). Созданная так группа — ручная и подтверждённая (сплошной зелёный).
  2. Получите предложения для остального. Выровнять между опорными точками (текст) рассчитывает между двумя опорными точками наиболее вероятные соответствия по объёму текста каждой строки. Окно показывает предложения: оставьте подходящие, затем нажмите Сохранить выделенное. Они сохраняются как требующие проверки (синий пунктир).
  3. Проверьте и подтвердите. Внизу выберите фильтр На проверку и просматривайте группы кнопками Далее ▶ (F8) и ◀ Назад (Shift+F8). Выбранная группа выделяется розовым на обоих изображениях. Подтвердить и далее (Alt+V) подтверждает её и переходит к следующей.
  4. Исправьте. Чтобы добавить строку в группу, выделите её вместе с одной из строк группы и выполните Связать строки. Чтобы убрать строку из группы, выделите её и выполните Разъединить. Исправленная группа становится ручной (зелёной) и защищённой.
  5. Обработайте отсутствия (см. ниже), затем закройте окно и сохраните проект.

Выделение строк

  • Щелчок по строке выделяет её (оранжевым) и заменяет выделение у этого свидетеля на всех его страницах.
  • Ctrl+щелчок добавляет или убирает строку; Shift+щелчок выделяет ряд строк в порядке чтения свидетеля, в том числе с переходом на другую страницу.
  • Щелчок по уже связанной строке показывает розовым соответствующие ей строки у другого свидетеля (при необходимости со сменой страницы). Розовый цвет никогда не означает выделения.
  • Колёсико мыши: масштаб; перетаскивание: перемещение изображения; двойной щелчок: увеличение строки. Вписать показывает страницу целиком.
  • Текст HTR показывает текст строк под изображением (текст TEI, если привязка TEI действительна). Контуры строк скрывает или показывает контуры; Снять выделение очищает выделение.

Видимые контуры позволяет показывать только Несвязанные строки или только Автоматические связи на проверку, чтобы найти то, что осталось сделать.

Список групп

Внизу поле Проверка фильтрует группы: Все группы, На проверку, Подтверждённые, Подтверждённые отсутствия, Устаревшие. Каждая группа описана в списке своим состоянием и строками, обозначенными как страница:строка (метка страницы, номер строки). Можно выделить несколько групп (Ctrl, Shift) и выполнить Подтвердить выделенное….

Локальный пересчёт… заново рассчитывает предложения только для интервала, следующего за выбранной опорной точкой, например после добавления новой опорной точки.

Подтверждённые отсутствия

Если у строк одного свидетеля нет соответствия в другом, выделите их только с одной стороны, затем выберите Другие действия → Подтвердить отсутствие выбранных строк (Ctrl+Shift+A). Они перестают быть «несвязанными» и показываются красным. Удалить выбранные отсутствия из списка отменяет отсутствие, выбранное с фильтром Подтверждённые отсутствия.

Устаревшие группы

Если назначить странице другой файл ALTO/PAGE (исправленную сегментацию), её строки могут измениться. Перед заменой программа сообщает, сколько групп ссылается на эти строки; после замены группы, у которых изменилась строка, помечаются «[устарела]». Фильтр Устаревшие выводит их список. После проверки по изображениям Подтвердить заново… восстанавливает их; в противном случае разъедините их. Исправленный порядок чтения страницы при этом сбрасывается.

Другие действия

  • Удалить выбранные группы из списка и Отметить как неуверенное действуют на группы, выбранные в списке.
  • Предложить по HTR (необязательно) ищет соответствия по сходству текста HTR в строках. Заранее ничего не выбрано: выберите предложения, которые нужно сохранить.
  • Порядок чтения и интервалы… исправляет порядок страниц, областей (столбцов) и строк свидетеля, если сегментация задаёт его неверно, и показывает интервалы между опорными точками.
  • Старая геометрическая интерполяция (совместимость) и Старое дополнение оставшихся строк (совместимость) — прежние методы, сохранённые для проектов, в которых они использовались.

Вкладка Текстовый вид (необязательно) показывает строки обоих свидетелей в виде текста. Команды действуют на выделение в открытой вкладке.

10. Шаг 4: завершение и экспорт

Обновить сводку подводит итог по свидетелям и синхронизациям и сообщает об изменённых строках или ненайденных файлах.

Проверка согласованности

Проверить согласованность проекта… проверяет проект, ничего в нём не изменяя: активные строки и связанные страницы каждого свидетеля, подтверждённые группы и отсутствия каждой пары, отсутствующие или устаревшие ссылки, ненайденные файлы. Выполняйте эту проверку перед каждым экспортом.

Предварительно заполненный проект Varians

Создать предварительно заполненный проект Varians… записывает в пустую папку проект, который Varians открывает без доработки:

  • project.xml: свидетели, их изображения (манифест IIIF или пути к локальным изображениям) и опорный свидетель;
  • xml/edition.xml: издание TEI опорного свидетеля или пустое издание TEI, если его нет;
  • alignments/<сигла>.json: синхронизация каждого свидетеля, только подтверждённые соответствия;
  • rendering/, i18n/, web_output/: обычные папки проекта Varians;
  • RAPPORT_EXPORT_VARIANS.txt: отчёт об экспорте;
  • в некоторых случаях iiif/: HD-копии изображений IIIF, если они есть у всех нужных страниц.

Изображения остаются на своих местах: проект ссылается на них (строки находятся в файлах синхронизации). Экспорт отклоняется, если папка не пуста, если сигла содержит точку, / или \, если у опорного свидетеля несколько изданий TEI, если у свидетеля смешаны изображения IIIF и локальные или если какой-либо файл не найден.

Экспортировать JSON для Varians

Экспортировать JSON для Varians… служит для добавления или обновления свидетелей в существующем проекте Varians (Сценарий B). Выберите свидетеля отсчёта (опорного свидетеля проекта Varians), подтвердите, затем выберите пустую папку. Программа записывает в неё:

  • validated/<сигла>.json: по файлу на свидетеля, только подтверждённые соответствия;
  • working/<сигла>.json: те же соответствия плюс неподтверждённые предложения;
  • rapport_export.json: подсчёты и проверки экспорта.

Varians не знает состояний Varians-Synchro: импортируйте validated/, если только вы сознательно не проводите эксперимент. Экспортируются только прямые синхронизации со свидетелем отсчёта, без выведения через третьего свидетеля. Если у свидетеля нет ни одного соответствия, пригодного для экспорта, программа сообщает об этом до экспорта и называет причину.

11. Формат файлов синхронизации (JSON)

По одному файлу на свидетеля, в кодировке UTF-8, в формате tei-manuscript-alignment версии 1, который читает Varians. Файл опорного свидетеля описывает его строки; файл каждого другого свидетеля описывает его собственные строки и связывает их со строками опорного.

Как их использует Varians

  • Строки файла опорного свидетеля, в порядке файла, по одной соответствуют элементам <lb edRef="#PIVOT"/> издания: первая строка — первому <lb/>, и так далее. Varians проверяет, что их число совпадает.
  • Ключ опорного свидетеля имеет вид id_страницы::строка: он остаётся действительным, пока страница сохраняет свой идентификатор и свой файл ALTO/PAGE. Поэтому нового свидетеля существующего проекта нужно выравнивать в том же проекте .vsynch (Сценарий B).
  • Когда текст доходит до строки опорного свидетеля, Varians показывает у каждого другого свидетеля строку или строки, чьи base_keys указывают на неё.

12. Файлы, резервные копии и устранение неполадок

Файл проекта

  • Вся работа хранится в файле .vsynch: свидетели, содержимое импортированных файлов ALTO/PAGE, связи, игнорируемые строки, порядок чтения, синхронизации. Исходные файлы никогда не изменяются.
  • Сохранение надёжно: файл заменяется за одну операцию, а предыдущая версия сохраняется в <проект>.vsynch.bak. Чтобы вернуться к ней, скопируйте этот .bak под новым именем с расширением .vsynch и откройте его.
  • Команды «Сохранить как» нет: чтобы сохранить версию, скопируйте файл .vsynch.
  • Проект с относительными путями (как поставляемый пример) открывается из любой папки; при сохранении пути записываются полностью.
  • Изменение файла ALTO/PAGE на диске после импорта не меняет проект; об этом сообщает сводка. Чтобы использовать исправленную сегментацию, импортируйте новый файл и свяжите его со страницей (затронутые группы станут устаревшими).
  • При закрытии программы, открытии или создании проекта предлагается сохранить текущие изменения.

Частые проблемы

  • «Перед выравниванием привяжите страницы ALTO к обоим свидетелям»: у одного из двух свидетелей ещё нет ни одной страницы, связанной с файлом строк (Шаг 2).
  • Изображение IIIF недоступно: сервер не отвечает; связи при этом не теряются. Повторите попытку позже или скачайте HD-копии.
  • Контуры смещены относительно изображения: у изображения и файла ALTO/PAGE разные пропорции (об этом сообщает строка состояния); проверьте, что файл действительно относится к этому изображению.
  • Экспорт отклонён: выбранная папка не пуста или сигла содержит точку, / или \.
  • В Varians строки опорного свидетеля не соответствуют тексту: число <lb edRef="#PIVOT"/> отличается от числа активных строк опорного свидетеля (забытые игнорируемые строки или недостающие <lb/>). Найти расхождение помогают Диагностика рукописей… в Varians и привязка TEI в Varians-Synchro.
  • В Varians связи файла не соответствуют ни одной строке опорного свидетеля: синхронизация опорного свидетеля создана не в том же проекте .vsynch (см. Сценарий B).
  • Работа со Spyder: запускайте run.py; программа открывается в отдельном процессе, чтобы не мешать консоли Spyder. Журнал запуска находится в ~/.varians_synchro/logs.
